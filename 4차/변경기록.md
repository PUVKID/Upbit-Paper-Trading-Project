# 4차 변경 기록

코드 변경의 출발점은 `efd88ce80887dc64fc1166415ac90944feed429f`이며, 공개 통합의 직전 기준은 상세 자료·차수를 추가한 `620b03e376a69e8a230b39e0e87dd8a9055721aa`입니다. [전체 비교](전체비교.md)는 후자를 기준으로 합니다. 기존 원격 보존자료와 차수·전체 비교·화면 링크를 유지하고 README·차수 색인에 4차 정책을 함께 연결했습니다. 복구 시점의 기존 자료·계좌·모델은 그대로 유지합니다.

## 변경 내용

- `4차/research_control.py`, `engine.py`, `supervisor.py`: 초기 50GB 연구와 명시 요청당 새 2GB 연구를 영속 상태로 구분합니다. 연구 대기와 실제 학습 시간 제한을 분리하며 모의매매는 별도 실행합니다. 정상 완료 산출물과 상태 기록 사이의 중단 복구를 검사합니다.
- `3차/external_data.py`: 공식 체크섬이 일치해도 내부 체결 순서가 잘못된 원본은 해시별로 격리합니다. 원본과 유효 부분 자료는 보존하며 해당 아카이브를 적재 완료 바이트로 계산하지 않습니다. 저장·권한·DB 오류는 내용 오류로 숨기지 않습니다.
- `engine.py`의 `CandleStore.summary`: 일관된 읽기 트랜잭션에서 커버링 인덱스 집계와 그룹별 기본키 조회를 사용합니다. 최소 시각을 봉 간격으로 추정하지 않으며 기존 결과와 일치하는 회귀 검사를 추가합니다.
- `dashboard.py`, `web/app.js`: 자료 준비와 추가 요청 대기를 구분하고 이전 학습의 100% 진행률을 대기 화면에 재사용하지 않습니다. 화면 구조·3D 모델·디자인은 변경하지 않습니다.
- `tests/test_external_data.py`, `tests/test_external_dashboard.py`, `tests/test_summary_throughput.py`, `tests/test_research_control.py`, `tests/test_research_supervisor.py`: 격리·대기 표시·집계 일치·연구 순서·실패 복구·감독 시간 제한을 검사합니다.
- `engine-config.json`, `4차/engine-config.json`, README와 차수 문서: 최신 두 트랙 계약, 실제 관측, 전체 차수와 비교 연결을 기록합니다.

주석·공백을 포함한 실제 추가·수정·삭제 목록과 전체 비교는 [전체 비교](전체비교.md)에 기록합니다. 이전 차수와 수리 전 원본은 보존합니다.

## 정체 원인

적재량 7,067,731,134바이트와 체크섬 검증량 7,832,698,113바이트는 서로 다른 지표입니다. `BTCUSDT-aggTrades-2026-02.zip`은 공식 체크섬이 일치했지만 내부에 역행·중복된 체결 블록이 있었습니다. 기존 반복 재시도가 다음 정상 아카이브 처리를 막았습니다. 이 자료를 정렬·중복 제거하여 정상 원본으로 가장하거나 50GB 목표에 포함하지 않습니다.

수정본을 연구 제어 변경과 함께 배포하려다 기존 수집기의 정체를 오래 남겼습니다. 수집기 선배포 때에는 루트에서 실행한 모듈 검사와 실제 스크립트 진입점의 모듈 경로 차이로 시작 직후 종료되는 결함도 확인했습니다. 관리 명령의 PID 반환만으로 수집 정상 동작을 판정하지 않습니다. 실제 데이터 증가와 모의매매 판단 갱신을 별도로 확인합니다.

## 검증 범위

진입점 수정 뒤 Linux 외부 수집기 집중 검사 34개가 통과했습니다. 프로젝트 바깥 작업 경로와 비워진 PYTHONPATH에서 실제 절대 경로 스크립트로 형제 연구 모듈을 불러오는 회귀 검사를 포함합니다. 호스트 정적 검사 104건도 통과했습니다. Linux 전체 보충 회귀 303개 통과는 별도 관측이며 공식 독립 검사의 시간 제한과 최종 소스 검사를 대체하지 않습니다.

대시보드의 실제 자료 준비 화면과 통제된 추가 요청 대기 응답을 1440×900·390×900에서 확인했습니다. 가로 넘침과 페이지 오류는 없었습니다. 통제 응답은 초기 연구의 실제 완료 증거가 아닙니다.

집계 회귀 검사는 통과했으나 별도 운영 읽기 성능 측정은 120초 제한으로 중단됐습니다. 이후 정상 수집 회차가 완료된 관측과 통제된 성능 개선 수치를 혼동하지 않습니다. CUDA의 작은 실제 적합 점검도 대용량 연구 완료나 금융 성과가 아닙니다.

수집기 수정 배포 후 실제 적재량은 7,067,731,134바이트에서 7,218,036,748바이트로 증가했습니다. 격리 경고 1건을 유지한 채 다음 정상 파일로 넘어갔으며 현재 수집 오류는 해소됐습니다. 이는 복구 관측이며 50GB 확보, 신규 모델 성적, 수익성 향상이나 정확도 100%는 주장하지 않습니다.

최종 독립 검증과 원격 확인은 동결 묶음에 대응하는 별도 비공개 영수증으로 구분합니다. 이 변경 기록이나 구현자 보조 검사만으로 전체 완료를 판정하지 않습니다.

공개 제외: 대용량 원시 아카이브, SQLite/WAL, 학습 모델, 계좌, 운영 로그, 개인 지침과 검증 영수증입니다. 새 논문·원고·제품 디자인·실제 주문 기능은 추가하지 않습니다.
