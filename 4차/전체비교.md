+# 4차 두 트랙 연구와 중단 지점 복구
+
+외부 자료 수집과 GPU 연구, 업비트 현물 모의매매를 기존 데이터에서 이어 실행하는 복구 차수입니다. 실행 경로와 계좌를 새로 만들지 않습니다.
+
+## 복구 범위
+
+공유 컨테이너는 실행 중이었으나 프로젝트 프로세스가 없었고, 로컬 대시보드는 HTTP 503을 반환했습니다. 기존 프로젝트 시작 도구로 감독 프로세스와 외부 수집기를 시작했습니다. 공유 컨테이너나 다른 연구 작업은 재시작하지 않았습니다. 컨테이너 안의 프로젝트 프로세스가 사라진 저수준 원인까지 확인된 것은 아닙니다.
+
+기존 업비트 시세·외부 아카이브·모델·장부를 이어 사용합니다. 원금 합계 1,000만원과 기존 계좌 시작 시각을 보존하며 실제 주문·외부 알림·강제 거래는 추가하지 않습니다. 노트북 셀과 웹 디자인도 변경하지 않습니다.
+
+## 실행 순서
+
+1. 검증된 고유 외부 아카이브 50GB를 적재할 때까지 수집합니다.
+2. 종목별 최신성·자료 범위·스키마 조건도 충족하면 GPU 초기학습을 시작합니다.
+3. 학습을 한 회차 완료하면 다음 연구를 자동으로 시작하지 않고 사용자 요청을 기다립니다.
+4. 이후 명시 요청마다 그 시점의 실제 적재량보다 새로운 고유 자료 2GB를 추가 수집한 뒤 학습을 한 회차 진행합니다.
+5. 기존 모델의 현물 모의매매 판단과 보유분 청산은 자료 준비·학습·요청 대기와 별도로 계속 진행합니다.
+
+[두 트랙 계약](docs/두트랙_연구계약.md)이 이전 3차의 자동 증분 재학습 방식을 대체합니다. API 요청당 200개 완성봉 저장과 추론용 최신 시세 갱신은 새 연구 요청과 다릅니다. 마지막 파일의 초과분을 다음 2GB 요청에 재사용하지 않습니다.
+
+`waiting_data / download`는 준비 대기이며 GPU 모델 적합 완료를 의미하지 않습니다. CUDA 실제 적합 점검은 별도의 작은 기능 검사로, 새 대용량 모델의 학습 성적이나 수익 근거가 아닙니다. 대용량 파일은 재시작 때 전체 무결성 재확인 시간이 필요합니다.
+
+## 관측과 한계
+
+복구 후 모의매매 판단이 연속 정상 완료됐으며 외부 자료 적재량도 약 6.00GB에서 6.49GB 이상으로 늘었습니다. 이는 복구 시점의 관측이며 현재 값은 [로컬 대시보드](http://127.0.0.1:8765/)에서 확인합니다. 아직 50GB 확보·신규 모델 성적·수익성 검증 완료를 주장하지 않습니다.
+
+이전 원시체결 순서 검증 오류와 복구 후 진행 여부는 구분해 검사합니다. 잘못된 자료를 정상 처리한 것으로 기록하거나 거래 수를 맞추기 위해 신호를 만들지 않습니다.
