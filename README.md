## 11차 TimesFM 사전학습 모델의 Zero-Shot 비교

**PC 전용 zero-shot GPU 실험 10회 완료 후 중지** 상태입니다. 원래 계획의 7회와 잔여 2회, 자료 부족에 따른 대체 1회로 구성되며, 원래 10개 anchor를 모두 완료한 것은 아닙니다. 추가 학습은 0회이며 자동 반복 일시정지, 11차 STOP, 기존 6차 pause와 7·8차 STOP, 5코인 모의매매를 유지합니다. 최종 검증과 원격 반영은 별도 영수증으로 관리합니다.

TimesFM2.5 200M의 처리 창은 56,320개(시장 56,300개와 재로드 probe 20개), validation 방향 표본은 28,150개이며 가중 방향 일치율은 49.136767%입니다.

cash 7회와 plain 3회 중 기본 비용 거래 3회는 모두 손실이어서 후보를 채택하거나 가상투자에 적용하지 않았습니다. 방향 일치율은 60분 종가 변화 방향에 대한 값이며 승률이나 3클래스 정확도가 아닙니다.

[회차별결과](11차/README.md) · [집계](11차/실험결과.json) · [보완계획](11차/실행보완계획.json) · [변경기록](11차/변경기록.md) · [전체비교](11차/전체비교.md). 후향 평가, 사전학습 노출 미확인, 지평 중첩, 실호가와 비용의 한계를 유지합니다. 회차 수익을 합산하지 않으며 수익, 정확도 100%, 낙폭 10% 이내를 보장하지 않습니다.

고정 가중치의 문맥512·예측12봉, 2일 정책 선정과 2일 후속 평가, 동일 진입 기회·비용1배/2배, 저장·재로드·중단 조건을 [11차 코드별 상세 안내](11차/README.md)에 정리했습니다.

회차 경과시간 합833.041977초와 전체 벽시계1,003.807609초를 구분합니다. 이번 안내 정리에서 모델·앱·실험을 다시 실행하지 않았습니다.

<a name="-10차-비용-차감-수익-연구와-거래-장부-진단"></a>
## 10차 비용 차감 수익 연구와 거래 장부 진단

실제 CUDA 적합 30회와 저장·재로드 검증을 완료했지만, 신규 후보는 거래 수와 순수익 기준 미달로 채택하지 않았습니다. 두 fold의 후속 평가는 현금 정책으로 0거래·0수익이며, 기존 모델 비교는 학습 노출이 있는 후향 진단입니다. 업비트 완료 OHLCV 9시간봉 연구이며 외부 50GB 전체 학습, 수익 개선, 자동 승격을 주장하지 않습니다. [10차 결과](10차/README.md) · [실험 집계](10차/실험결과.json) · [변경 기록](10차/변경기록.md) · [전체 비교](10차/전체비교.md). 최종 검증과 원격 반영은 별도 영수증으로 관리하며 GPU 성과와 구분합니다. 수익·정확도100%·낙폭10% 이내를 보장하지 않으며 기존 자동 학습 중지와 모의계좌는 보존합니다.

<a name="-독립-트랙과-연구-상태의-연결"></a>
## 독립 트랙과 연구 상태의 연결

루트 engine.py와 설정은 공개 시세 수집·연구·모의매매를 연결하고,3차 external_data.py는 공식 외부 아카이브의 검증·고유 저장·최근 자료 준비를,4차 research_control.py는 요청별 연구 상태를 관리합니다.5차는 월 경계 수집 계획 보완,6차는 후속 연구,7차는 Chronos-2 별도 연구,8차는 고정 자료 반복 적합,9차는 자동 학습 중지와 검증 계획입니다.

초기 외부 고유50,000,000,000바이트를 준비한 뒤 연구 한 회차를 수행하고 완료 뒤 명시 요청을 기다리는 것이4차 계약입니다. 추가 요청은 당시 실제 고유 적재량+2,000,000,000바이트로 목표를 동결합니다. 압축해제·DB·복제 크기로 채우지 않으며 초기 미완료·중복 요청을 거부합니다. 모의매매와 최신 시세 갱신은 별도 트랙으로 기존 검증 모델과 장부를 사용합니다.

ResearchControl은 collecting→training→completed와 batch·claim·attempt를 JSON에 보존합니다. 상태 잠금과 학습 잠금을 분리하고 완료 보고서·모델/manifest 해시를 요청과 결합합니다. 모델 실패는 원문과 시도 수를 남기며, 정상 결과 저장 뒤 상태 기록만 중단됐다면 완료 결과를 검증해 남은 처리를 복구합니다. 학습 완료와 promote 여부를 따로 기록합니다.

5차의 대기는 단순50GB 부족이 아니라 최근14일98% 커버리지 미달이 원인이었습니다. bootstrap_plan은 직전 월별 자료와 이번 달·최근14일 완료 UTC 날짜의 일별 원본을 중복 없이 최근 순으로 요청합니다.2026-11-02 준비 표시가 참으로 바뀐 관측은 GPU 적합 완료·수익 향상과 다릅니다.

7차 Chronos-2는 RTX4090 CUDA에서40,998행·context192·batch8·50step의 추가 학습과 저장/재로드를 기록했습니다. 후속20창 상대MAE0.210743%는 종가 유지0.204550%보다 나빴고 방향 일치율20%는 거래 승률이 아닙니다.8차는 같은 train/tune으로50step fit10회이며 학습 손실4.521545→3.839211, 튜닝 손실7.453165→8.106275를 기록했습니다. 새 독립평가는 없고 candidate_ready/promote=false입니다.

9차는 work/service/TRAINING_PAUSED와7·8차 STOP 경계로 새 적합을 중지합니다. 과거 실행 안내를 현재 자동 재개 명령으로 사용하지 않습니다. 기존 체크포인트·시세·모의계좌를 보존하며 후속 연구는 비용·시점 분리·미사용 평가·승격 계약을 정한 뒤 명시 재개해야 합니다. 이 중지는 임의 Python 전체를 막는 운영체제 보안 기능은 아닙니다.

<a name="-10차-비용-차감-수익-연구와-거래-장부-진단-1"></a>
### 10차: 비용 차감 수익 연구와 거래 장부 진단

10차는 평균·q10·q90 수익 모델을 2개 시간 구간과 5개 시장에 적합하고 현금·추세·기존 모델과 비교합니다. 보존된 집계에는 CUDA 적합 30회와 모델 재로딩 검증이 기록되어 있지만 신규 정책은 후속 평가에서 거래 0회로 미채택입니다. 외부 50GB 기초학습·독립 최종 시험·자동 승격은 이 실행의 결과가 아닙니다. [함수·설정·기간·저장·관측 상세](10차/README.md)와 [집계 JSON](10차/실험결과.json)에서 정책 선정 구간과 후속 평가를 구분해 읽을 수 있습니다.

현재 기본 엔진의 `Portfolio`는 `max_drawdown=0.1`을 신규 매수 차단에 연결합니다. `drawdown_limit`은 bool·비유한 값과 0~1 열린 구간 밖의 값을 거부하고 복원 시 고점·MDD·차단 상태를 검증합니다. `observe_drawdown`은 차단 시각을 유지하며 날짜 변경·모델 교체로 이를 해제하지 않습니다. 손절·익절·만료·매도 처리는 유지되므로 10% 손실 상한을 보장하는 장치는 아닙니다.

`Portfolio.process`의 `clean_context`는 진입 근거와 현재 청산 판단을 분리하며 기존 `invalid`·`partial_invalid`를 보존합니다. 잘못된 진입 근거는 `entry_context_invalid=true`, `entry_model_run=null`로 기록합니다. 호가 기록은 원호가·관측 시각·나이·위험 평가 가격 출처·수수료·슬리피지를 담습니다. 과거 누락 정보를 현재 모델의 판단으로 채우지 않습니다.

`10차/trade_diagnostics.py`는 매수 수수료를 포함한 평균원가를 매도 수량 비율로 배분하고 부분 매도·추가 진입·미청산 잔량·현금·실현손익을 대조합니다. 불완전 장부는 `incomplete`, 잘못된 체결 자료는 `rejected`로 분리합니다. 기본 입력은 `work/paper/state.json`, 출력은 `10차/work/trade-diagnostics.json`이며 최대 32MiB의 안정된 스냅샷을 읽고 원자 교체로 출력합니다. 과거 누적 계좌 진단을 10차 신규 모델의 수익으로 합산하지 않습니다.

`dashboard.py`의 `return_research`는 `10차/work/status.json`에서 schema 1, 허용 상태·단계, 적합 수 0~30, 구간 수 1~2, 목적과 승격 금지를 검사합니다. 완료 상태는 적합 수가 계획과 같고 평가가 수행되었을 때만 표시합니다. 비교 행은 최대 60개 중 유효한 후보·비용·유한 수익·MDD·거래 수만 전달하며 파일 경로와 오류 원문은 제외합니다. `cuda:0`도 GPU 확인 표시가 함께 있을 때만 전달합니다. 화면은 10차 수익 연구를 8차 반복 추가학습 및 현재 모의계좌와 구분해 완료 모델 수·구간·미채택·운용 미적용을 보여 줍니다. 계좌 화면의 낙폭 한도 비율과 매수 차단 여부는 장부의 유효한 수치·bool에서 읽습니다.

## 주요 기술과 실행 경계

분석에 쓸 데이터는 NumPy·pandas로 구성하고 XGBoost를 학습합니다. 운영 데이터는 SQLite와 JSON으로 기록합니다. `collector`, `trainer`, `paper`, `experiment`, `check-gpu`가 엔진의 명령 진입점입니다.

`execution_probe.py`는 별도의 2,500만 원 진단 계좌에서 BTC 매수·매도 경로를 검사합니다. 전략 계좌의 기본 1,000만 원과 구분하며, 진단의 최대 배정 비율은 0.1%입니다. 이 결과를 전략 계좌의 거래나 수익과 합치지 않습니다. `healthcheck.py`는 계좌·데이터·장치 근거의 조건을 확인하며, 그 통과가 투자 성능을 의미하지 않습니다.

<a name="-완료봉에서-매매-신호까지"></a>
### 완료봉에서 매매 신호까지

수집기는 공개 캔들과 호가의 GET 요청만 허용합니다. 완료되지 않은 봉은 저장하지 않고, 같은 종목·시간봉·시각의 기존 봉은 `INSERT OR IGNORE`로 보존합니다. 누락된 시각에 가짜 봉을 채우지 않습니다.

특성은 수익률, 변동성, 이동평균, 거래량, 봉의 몸통과 범위 등으로 구성합니다. 여러 시간봉은 과거 방향의 `merge_asof`로 결합합니다. 라벨은 다음 봉 시가에서 진입해 지정한 미래 시각의 종가로 계산하며, 결측봉이 있어도 단순 행 이동으로 다른 시각을 대신하지 않습니다.

### ⏱️ 시간 구간과 모델 승격

학습 → 가중치 조정 → 확률 보정 → 거래규칙 선택 → 후보 검증 → 최종 시험을 구분합니다. 학습과 평가 경계에는 예측 기간을 고려한 간격을 두며, 최종 시험 구간은 노출 예약을 먼저 기록해 같은 구간의 반복 사용을 막습니다. 예약 후 실패한 시도도 사용 이력에서 지우지 않습니다.

앙상블 가중치는 조정 구간에서, 온도 보정은 별도 보정 구간에서 정합니다. 거래규칙에는 거래하지 않는 후보도 있습니다. 후보 승격은 같은 검증 구간에서 로그 손실과 `순수익 - 0.5 × 최대 낙폭`을 비교하며, 라벨 구성이 다른 경우에는 거래 지표 비교로 구분합니다. 단순히 새 학습이 끝났다는 이유로 운영 모델을 교체하지 않습니다.

<a name="-모의계좌의-주문-조건"></a>
### 모의계좌의 주문 조건

모의체결은 호가의 가격과 잔량을 순서대로 소비합니다. 잔량이 부족하면 부분체결과 미체결금액을 남기며, 수수료·슬리피지를 반영합니다. 과거 평가에서는 다음 봉 시가를 사용하고, 현재 모의계좌에서는 추론 후 새로 가져온 호가를 사용합니다.

오래된 특징, 미래 시각, 중복 처리 봉은 신규 매수를 막습니다. 일일 손실 한도에 도달해도 기존 포지션 청산 경로는 유지하며, 현금·종목별·전체 배정 한도를 함께 적용합니다. 거래 이력과 계좌 상태는 SQLite 거래 단위로 기록합니다.

<a name="-보존한-v4-실험과-현재-엔진"></a>
### 보존한 v4 실험과 현재 엔진

[이전 v4 노트북](보존자료/원본/upbit_auto_trader_v4.ipynb)은 4코인·초기 100만 원·5분봉에 15분/1시간 피처를 결합하고, LightGBM·XGBoost·GRU·LSTM·Transformer를 비교하던 별도 실험입니다. 첫 Markdown의 1시간봉·1.5% 설명과 실제 설정인 5분봉·0.6%가 다릅니다. 현재 5코인 엔진에서는 구간 분리·승격·모의체결 조건을 별도로 구성했습니다.

v4에는 `signal_confidence(self, prob)` 정의와 두 호출부의 `(prob, ticker)` 인자가 맞지 않는 부분이 남아 있습니다. 상위 시간봉 피처의 단순 전방 채움, 예측 기간을 비워 두지 않은 분할 경계, Walk-Forward 평가 구간을 LightGBM 조기 종료에 사용한 점도 평가 해석의 제약입니다. 해당 보존 노트북의 전체 실행 성공이나 완전히 독립적인 시험 성능을 보증하지 않습니다.

<a name="-대시보드의-표시-범위"></a>
### 대시보드의 표시 범위

대시보드는 저장된 계좌·학습·진단 자료를 GET 요청으로 읽습니다. 3D 막대는 과거 평가의 예측 표본 개수이며 현재 매매 확률이나 실시간 주문 신호가 아닙니다. WebGL을 사용할 수 없으면 2D 표시로 전환하고, 자료가 없으면 대기 상태를 표시합니다. 화면 모션 정지는 수집·학습·모의체결 프로세스를 중단하지 않습니다.

저장된 기록과 코드의 기본값을 바탕으로 모의거래 흐름을 설명합니다.
