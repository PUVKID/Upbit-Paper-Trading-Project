### LEVEL 1 · 처음 읽는 분을 위한 동작과 결과

10차는 비용을 뺀 수익을 예측하는 후보를 두 기간에서 시험하고, 기존 가상계좌의 거래 장부를 별도로 진단한 차수입니다. 평균·낮은 쪽 q10·높은 쪽 q90 모델을 5시장×2기간×3종류로 30개 적합했습니다. 새 후보는 두 후속 기간의 기본/2배 비용에서 거래 0회·수익 0·MDD 0으로 현금을 유지했고 채택되지 않았습니다. 거래를 하지 않아 손실도 없었던 결과를 수익성 성공으로 보지 않습니다. 기존 장부의 DOGE 매도35건·순손익 -440,917.75원·수수료43,529.44원은 새 후보 결과와 다른 자료입니다.

#### LEVEL 1 · 수익률 연구의 모듈과 처리 순서

10차는 평균 수익률과 하위·상위 분위수를 함께 추정하고, 거래 비용과 낙폭을 반영한 정책을 현금 보유와 비교합니다.

`return_research.py`는 유한한 두 평가 구간을 실행하는 연구 도구이며, `trade_diagnostics.py`는 기존 모의계좌 장부의 매수·매도 연결과 손익을 읽는 별도 도구입니다.

**함수:** `validate_settings`

**맡은 처리와 경계:** 알 수 없는 설정 키, 잘못된 정수 범위, bool을 숫자로 넣은 값, 유한하지 않은 값을 거부합니다. 고정한 기간·예측 지평도 검사합니다.

**함수:** `fold_plans`

**맡은 처리와 경계:** 완료된 5분봉 기준시각에서 두 구간을 만들고 학습·튜닝·정책 선택·후속 평가 시간을 순서대로 분리합니다.

**함수:** `prepare_fold`

**맡은 처리와 경계:** 시장별 완료 봉에서 특징과 목표값을 구성하고 기존 모델의 학습 노출 범위, 제외 구간, 실제 행 수를 기록합니다.

**함수:** `fit_return_model`

**맡은 처리와 경계:** 시장·구간마다 평균, q10, q90 모델을 CUDA로 적합합니다. 평균은 제곱오차, 분위수는 0.1·0.9 분위수 손실을 사용합니다.

**함수:** `save_verified_model`

**맡은 처리와 경계:** UBJ 모델을 저장하고 다시 읽어 예측과 모델 해시를 대조합니다. 파일 생성과 재로딩 검증을 구분해 기록합니다.

**함수:** `select_policies`

**맡은 처리와 경계:** 정책 선택 구간에서 최소 거래 수·양의 순수익·낙폭 한도를 통과한 정책을 `순수익률 − 0.5 × MDD`로 비교합니다. 현금 점수 0을 넘지 못하면 거래 정책을 선택하지 않습니다.

**함수:** `review_eligibility`

**맡은 처리와 경계:** 선택에 쓰지 않은 후속 두 구간을 기본 비용과 2배 비용으로 평가하고 거래 수·구간별 수익·MDD 조건을 판정합니다.

**함수:** `run_study`

**맡은 처리와 경계:** 요청·진행·모델·구간 결과·최종 해시 목록을 저장합니다. 결과와 별개로 자동 승격을 수행하지 않습니다.


#### LEVEL 1 · 설정값과 입력 자료

**항목:** 기준시각

**10차 설정:** `2026-10-31T08:00:00Z`

**항목:** 구간 수·기간

**10차 설정:** 2개 구간, 학습 90일, 튜닝 2일, 정책 선택 2일, 후속 평가 2일

**항목:** 예측 지평

**10차 설정:** 5분봉 12개

**항목:** 모델

**10차 설정:** 최대 150회, 조기 종료 20회, 깊이 3, 학습률 0.05, `hist`, `cuda:0`, max_bin 128

**항목:** 반복 조건

**10차 설정:** seed 42, nthread 4, subsample·colsample_bytree 0.9, 최근 자료 가중치 반감기 30일

**항목:** 데이터 상한

**10차 설정:** 학습 100,000행, 원시 입력 300,000행, 분할 최소 100행

**항목:** 채택 조건

**10차 설정:** 구간별 최소 3회, 전체 최소 20회, 구간별 양의 순수익, MDD 0.1 이하

**항목:** 실행 보호

**10차 설정:** 최대 7,200초, 최소 여유 공간 20,000,000,000바이트


입력은 완료된 Upbit 5개 시장·9개 시간봉입니다. 이 실험은 4차의 외부 자료 50GB 기초학습을 수행한 결과가 아닙니다. 두 구간의 학습 창은 겹치므로 서로 독립된 두 연구의 성공으로 합산하지 않습니다.

설정 검증은 folds 1~2, rounds 2~150, early_stopping_rounds 2~20, depth 1~6, learning_rate 0.001~0.05를 허용합니다. 학습 행 상한은 100~100,000, 원시 행 상한은 1,000~300,000, 최소 분할 행은 100~100,000 범위입니다. 최소 구간 거래 수는 3~1,000, 총 거래 수는 20~10,000, max_drawdown은 0.001~0.1, max_seconds는 1~7,200, min_free_bytes는 20,000,000,000~1,000,000,000,000입니다.

누락 키에는 기본값을 합치되 학습·튜닝·정책·평가 기간과 horizon은 동결값과 같아야 합니다. folds=1은 입력으로 가능해도 최종 연구 검토의 두 구간 조건을 통과하지 못합니다.

정책은 일반 기대수익 방식과 불확실성 벌점 방식으로 나뉩니다. 벌점 계수는 0.25·0.5·1, 최소 순수익 기준은 0·0.0005·0.001이며 수수료·슬리피지를 반영합니다. 정책 선택 구간의 최고 수치와 후속 평가 수치를 섞지 않습니다.

`return_signals`는 비용 스트레스 비율을 `(0, 1]`에서 검증하고 평균·q10·q90이 모두 유한하며 분위수 폭이 음수가 아니고 평균이 양수일 때만 매수 후보를 만듭니다. `평균 − 벌점 × 분위수 폭`이 최소 기준을 엄격히 넘으면 신호 2, 나머지는 중립 1입니다. 현금 정책은 모두 중립을 반환합니다. 정책 점수가 현금과 같아도 현금을 유지합니다.

#### LEVEL 1 · 실행 조건·저장·중단

학습 진입에는 Linux 환경과 명시적인 `allow_training` 허용이 필요합니다. 실행 이름은 영문·숫자·밑줄·하이픈 1~80자이며 `10차/work/runner.lock`으로 중복 실행을 막습니다. 이미 존재하는 실행 폴더는 덮어쓰거나 자동 재개하지 않습니다. 정지 신호, 제한 시간, 여유 공간을 점검하며 기존 9차의 중지 정책과 이번 유한 실행의 허용 범위를 구분합니다.

`10차/work/status.json`은 현재 진행을 담고 `10차/work/runs/<run>/`에는 `request.json`, `manifest.json`, 구간별 `fold-1/`·`fold-2/`가 생깁니다. 각 구간에는 `data.json`, `policy.json`, `predictions.json`, `report.json`, `<시장>-<목표>.ubj` 모델과 해시·재로딩 근거가 남습니다. 실패 시 실행 폴더의 `failure.json`에 오류 종류·메시지·traceback·argv·cwd·진행 수를 기록하고 상태를 `stopped` 또는 `error`로 끝냅니다. 자동 재시도·자동 승격은 하지 않습니다. 명령 진입점은 `--once`·`--run`을 필수로 받고 `--allow-training`으로 해당 유한 실행을 허용합니다. 기본 설정은 `10차/return-research-config.json`이며 실제 실행 환경의 `engine-config.json`과 기존 DB·모델이 필요합니다.

진행 단계는 `prepare → fit → policy → validation → complete`이며 구간·시장·목표·반복 수·손실·GPU 확인 상태가 갱신됩니다. `Status.update`는 `0 ≤ completed_fits ≤ fit_calls ≤ max_fits ≤ 30`과 승격 금지를 검사한 뒤 원자 저장합니다. `10차/work/STOP`, SIGTERM, SIGINT는 유한 실행의 정지 경로로 연결됩니다. 적합 수가 동결 계획의 `folds × 15`와 다르면 완료로 저장하지 않습니다.

#### LEVEL 1 · 보존된 실험 집계와 미채택 결과

`실험결과.json`은 기존 실행의 집계입니다. CUDA 모델 적합 30개와 완료 30개, 모델 재로딩 검증이 기록되어 있습니다. 모델별 실제 반복 수는 21~150회, 학습 행은 24,780~25,237행이며 산출물은 85개입니다. 이번 문서 정리에서 학습을 새로 실행한 수치가 아닙니다.

일반 기대수익·불확실성 벌점·선택 정책은 두 후속 평가 구간과 두 비용 조건에서 모두 거래 0회, 순수익 0, MDD 0입니다. 현금 보유가 유지되었고 거래 수 부족과 구간별 양의 수익 조건 미달로 후보가 채택되지 않았습니다. `promotion=false`를 수익성 검증 성공으로 해석하지 않습니다.

정책 선택 구간의 한 시도는 순수익 약 0.13266%, MDD 약 0.28992%였지만 위험 조정 점수는 약 -0.000123으로 현금의 0보다 낮았습니다. 이것은 후속 평가 성적이 아니라 정책을 고르는 앞 구간의 수치입니다.

추세 기준선의 후속 순수익은 첫 구간 기본 비용 약 -3.75632%·2배 비용 -3.81247%, 둘째 구간 -3.38267%·-3.98338%입니다. 기존 분류 모델의 소급 비교는 첫 구간 +0.68186%·+0.53065%, 둘째 구간 +0.37101%·-0.12923%이지만 해당 평가 기간에 대한 학습 노출이 있어 독립 표본외 성적으로 사용하지 않습니다.

#### LEVEL 1 · 장부 진단과 기본 엔진의 거래 근거

`diagnose`와 `_reconstruct`는 매수 수수료를 포함한 취득원가를 수량 비율로 나눠 부분 매도의 원가를 계산합니다. 추가 매수와 남은 보유 수량을 함께 추적하는 평균원가 방식이며 FIFO가 아닙니다. 원장 누락·잔액 불일치·형식 오류는 `incomplete` 또는 `rejected`로 구분합니다. 과거 진입 근거가 없다고 현재 모델을 그 거래의 진입 모델로 채워 넣지 않습니다.

`stable_read`는 최대 3번 시도하며 연속 두 번 동일하게 읽힌 스냅샷을 사용합니다. 입력은 최대 32MiB이고 중복 JSON 키·비유한 숫자·링크·reparse·하드링크 등 허용하지 않는 입력을 거부합니다. 기본 입력 `work/paper/state.json`에서 읽고 기본 출력 `10차/work/trade-diagnostics.json`에 UTF-8 임시 파일·fsync·원자 교체로 저장합니다. 완전한 진단만 종료 코드 0이며 그 밖의 결과는 2입니다.

기존 누적 계좌의 매도 35건은 모두 DOGE였고 양수 1건·음수 34건, 순손익 -440,917.75원, 수수료 43,529.44원으로 집계되었습니다. 이 누적 장부와 10차 새 후보의 거래 0회 결과는 별개입니다. 과거 71건의 모델 메타데이터 누락도 장부 진단의 한계로 남습니다.

기본 `engine.py`의 `drawdown_limit`은 기본 0.1을 사용하며 bool·비유한 값·0 이하·1 이상을 거부합니다. `Portfolio` 복원은 초기 원금·모의 전용 표시·음수 잔액·고점·MDD·중지 기록을 검증합니다. `observe_drawdown`은 평가 고점과 현재·최대 낙폭을 갱신하고 한도 도달 시 `drawdown_halt`와 최초 시각을 보존합니다. 날짜 변경은 일일 매수 차단만 초기화하므로 최대 낙폭 차단은 해제되지 않습니다.

`Portfolio.process`는 같은 봉을 중복 처리하지 않으며 매수 전에도 낙폭을 확인합니다. 차단 중에도 손절·익절·만료·매도 신호 처리는 유지합니다. `clean_context`는 확률 3개·신호·유한 숫자·문자열 길이·시간봉을 검증하고 기존 `invalid`·`partial_invalid` 표시를 유지합니다. 매도 기록은 진입 당시 `entry_context`, 현재 `decision_context`, 실제/합성 호가·시각·비용의 `execution_context`를 나눕니다. 잘못된 진입 근거는 `entry_context_invalid=true`와 `entry_model_run=null`로 남겨 정상 근거처럼 재분류하지 않습니다.

현금 기준선도 두 fold·두 비용 조건에서0거래·0수익입니다. 비율은 JSON 원값에100을 곱해 반올림했으며 정책 선정 실험과 위 후속 평가를 합산하지 않습니다.

후속0거래를 신호 자체의 부재로 해석하지 않습니다. 첫 fold의 plain 정책 선정 실험은 최소값0 / 0.0005 / 0.001에서 각각12거래·-0.29141%, 7거래·-0.16772%, 1거래·-0.26488%였습니다. 비용 차감 우위가 확인되지 않은 실험을 억지로 매매 정책에 채택하지 않았습니다. 둘째 fold의 일부 plain 정책 실험은11거래·+0.13266%로 `eligible=true`였지만 MDD는 약0.28992%였습니다. 선정 점수 `net_return - 0.5 × MDD`는 `0.0013266337944870532 - 0.5 × 0.0028992335735867902 = -0.0001229829923063419`로 현금의0보다 낮아 최종 현금 정책이 선택됐습니다. 정책 실험의 양수를 후속 성과나 최종 채택으로 바꾸지 않습니다.

두 fold의 학습 구간은 겹치며 이번 연구는 독립 미사용 최종 시험이 아닙니다. 기존 모델 결과는 평가 기간의 학습 노출 때문에 `retrospective_diagnostic`이며 새 미사용 성능이나 신규 후보와의 독립 우열 검증으로 해석할 수 없습니다. 과거 실제 호가 부재에 따른 스프레드·정확한 체결비용 한계, 작은 청산 표본, 실제 운용과 후향 비교의 차이를 유지합니다. 기존 누적 계좌 진단도 위 신규 후보 성과와 합치지 않습니다.

#### LEVEL 2 · 수익률 연구의 모듈과 처리 순서

10차는 평균 수익률과 하위·상위 분위수를 함께 추정하고, 거래 비용과 낙폭을 반영한 정책을 현금 보유와 비교합니다.

`return_research.py`는 유한한 두 평가 구간을 실행하는 연구 도구이며, `trade_diagnostics.py`는 기존 모의계좌 장부의 매수·매도 연결과 손익을 읽는 별도 도구입니다.

**함수:** `validate_settings`

**맡은 처리와 경계:** 알 수 없는 설정 키, 잘못된 정수 범위, bool을 숫자로 넣은 값, 유한하지 않은 값을 거부합니다. 고정한 기간·예측 지평도 검사합니다.

**함수:** `fold_plans`

**맡은 처리와 경계:** 완료된 5분봉 기준시각에서 두 구간을 만들고 학습·튜닝·정책 선택·후속 평가 시간을 순서대로 분리합니다.

**함수:** `prepare_fold`

**맡은 처리와 경계:** 시장별 완료 봉에서 특징과 목표값을 구성하고 기존 모델의 학습 노출 범위, 제외 구간, 실제 행 수를 기록합니다.

**함수:** `fit_return_model`

**맡은 처리와 경계:** 시장·구간마다 평균, q10, q90 모델을 CUDA로 적합합니다. 평균은 제곱오차, 분위수는 0.1·0.9 분위수 손실을 사용합니다.

**함수:** `save_verified_model`

**맡은 처리와 경계:** UBJ 모델을 저장하고 다시 읽어 예측과 모델 해시를 대조합니다. 파일 생성과 재로딩 검증을 구분해 기록합니다.

**함수:** `select_policies`

**맡은 처리와 경계:** 정책 선택 구간에서 최소 거래 수·양의 순수익·낙폭 한도를 통과한 정책을 `순수익률 − 0.5 × MDD`로 비교합니다. 현금 점수 0을 넘지 못하면 거래 정책을 선택하지 않습니다.

**함수:** `review_eligibility`

**맡은 처리와 경계:** 선택에 쓰지 않은 후속 두 구간을 기본 비용과 2배 비용으로 평가하고 거래 수·구간별 수익·MDD 조건을 판정합니다.

**함수:** `run_study`

**맡은 처리와 경계:** 요청·진행·모델·구간 결과·최종 해시 목록을 저장합니다. 결과와 별개로 자동 승격을 수행하지 않습니다.

**항목:** 구간 수·기간

**항목:** 예측 지평

**10차 설정:** 5분봉 12개

**항목:** 모델

**10차 설정:** 최대 150회, 조기 종료 20회, 깊이 3, 학습률 0.05, `hist`, `cuda:0`, max_bin 128

**항목:** 반복 조건

**10차 설정:** seed 42, nthread 4, subsample·colsample_bytree 0.9, 최근 자료 가중치 반감기 30일

**항목:** 데이터 상한

**10차 설정:** 학습 100,000행, 원시 입력 300,000행, 분할 최소 100행

**항목:** 채택 조건

**10차 설정:** 구간별 최소 3회, 전체 최소 20회, 구간별 양의 순수익, MDD 0.1 이하

**항목:** 실행 보호

**10차 설정:** 최대 7,200초, 최소 여유 공간 20,000,000,000바이트


입력은 완료된 Upbit 5개 시장·9개 시간봉입니다. 이 실험은 4차의 외부 자료 50GB 기초학습을 수행한 결과가 아닙니다. 두 구간의 학습 창은 겹치므로 서로 독립된 두 연구의 성공으로 합산하지 않습니다.

설정 검증은 folds 1~2, rounds 2~150, early_stopping_rounds 2~20, depth 1~6, learning_rate 0.001~0.05를 허용합니다. 학습 행 상한은 100~100,000, 원시 행 상한은 1,000~300,000, 최소 분할 행은 100~100,000 범위입니다. 최소 구간 거래 수는 3~1,000, 총 거래 수는 20~10,000, max_drawdown은 0.001~0.1, max_seconds는 1~7,200, min_free_bytes는 20,000,000,000~1,000,000,000,000입니다.

누락 키에는 기본값을 합치되 학습·튜닝·정책·평가 기간과 horizon은 동결값과 같아야 합니다. folds=1은 입력으로 가능해도 최종 연구 검토의 두 구간 조건을 통과하지 못합니다.

정책은 일반 기대수익 방식과 불확실성 벌점 방식으로 나뉩니다. 벌점 계수는 0.25·0.5·1, 최소 순수익 기준은 0·0.0005·0.001이며 수수료·슬리피지를 반영합니다. 정책 선택 구간의 최고 수치와 후속 평가 수치를 섞지 않습니다.

`return_signals`는 비용 스트레스 비율을 `(0, 1]`에서 검증하고 평균·q10·q90이 모두 유한하며 분위수 폭이 음수가 아니고 평균이 양수일 때만 매수 후보를 만듭니다. `평균 − 벌점 × 분위수 폭`이 최소 기준을 엄격히 넘으면 신호 2, 나머지는 중립 1입니다. 현금 정책은 모두 중립을 반환합니다. 정책 점수가 현금과 같아도 현금을 유지합니다.

#### LEVEL 2 · 실행 조건·저장·중단

학습 진입에는 Linux 환경과 명시적인 `allow_training` 허용이 필요합니다. 실행 이름은 영문·숫자·밑줄·하이픈 1~80자이며 `10차/work/runner.lock`으로 중복 실행을 막습니다. 이미 존재하는 실행 폴더는 덮어쓰거나 자동 재개하지 않습니다. 정지 신호, 제한 시간, 여유 공간을 점검하며 기존 9차의 중지 정책과 이번 유한 실행의 허용 범위를 구분합니다.

`10차/work/status.json`은 현재 진행을 담고 `10차/work/runs/<run>/`에는 `request.json`, `manifest.json`, 구간별 `fold-1/`·`fold-2/`가 생깁니다. 각 구간에는 `data.json`, `policy.json`, `predictions.json`, `report.json`, `<시장>-<목표>.ubj` 모델과 해시·재로딩 근거가 남습니다. 실패 시 실행 폴더의 `failure.json`에 오류 종류·메시지·traceback·argv·cwd·진행 수를 기록하고 상태를 `stopped` 또는 `error`로 끝냅니다. 자동 재시도·자동 승격은 하지 않습니다. 명령 진입점은 `--once`·`--run`을 필수로 받고 `--allow-training`으로 해당 유한 실행을 허용합니다. 기본 설정은 `10차/return-research-config.json`이며 실제 실행 환경의 `engine-config.json`과 기존 DB·모델이 필요합니다.

진행 단계는 `prepare → fit → policy → validation → complete`이며 구간·시장·목표·반복 수·손실·GPU 확인 상태가 갱신됩니다. `Status.update`는 `0 ≤ completed_fits ≤ fit_calls ≤ max_fits ≤ 30`과 승격 금지를 검사한 뒤 원자 저장합니다. `10차/work/STOP`, SIGTERM, SIGINT는 유한 실행의 정지 경로로 연결됩니다. 적합 수가 동결 계획의 `folds × 15`와 다르면 완료로 저장하지 않습니다.

#### LEVEL 2 · 보존된 실험 집계와 미채택 결과

`실험결과.json`은 기존 실행의 집계입니다. CUDA 모델 적합 30개와 완료 30개, 모델 재로딩 검증이 기록되어 있습니다. 모델별 실제 반복 수는 21~150회, 학습 행은 24,780~25,237행이며 산출물은 85개입니다. 이번 문서 정리에서 학습을 새로 실행한 수치가 아닙니다.

일반 기대수익·불확실성 벌점·선택 정책은 두 후속 평가 구간과 두 비용 조건에서 모두 거래 0회, 순수익 0, MDD 0입니다. 현금 보유가 유지되었고 거래 수 부족과 구간별 양의 수익 조건 미달로 후보가 채택되지 않았습니다. `promotion=false`를 수익성 검증 성공으로 해석하지 않습니다.

정책 선택 구간의 한 시도는 순수익 약 0.13266%, MDD 약 0.28992%였지만 위험 조정 점수는 약 -0.000123으로 현금의 0보다 낮았습니다. 이것은 후속 평가 성적이 아니라 정책을 고르는 앞 구간의 수치입니다.

추세 기준선의 후속 순수익은 첫 구간 기본 비용 약 -3.75632%·2배 비용 -3.81247%, 둘째 구간 -3.38267%·-3.98338%입니다. 기존 분류 모델의 소급 비교는 첫 구간 +0.68186%·+0.53065%, 둘째 구간 +0.37101%·-0.12923%이지만 해당 평가 기간에 대한 학습 노출이 있어 독립 표본외 성적으로 사용하지 않습니다.

#### LEVEL 2 · 장부 진단과 기본 엔진의 거래 근거

`diagnose`와 `_reconstruct`는 매수 수수료를 포함한 취득원가를 수량 비율로 나눠 부분 매도의 원가를 계산합니다. 추가 매수와 남은 보유 수량을 함께 추적하는 평균원가 방식이며 FIFO가 아닙니다. 원장 누락·잔액 불일치·형식 오류는 `incomplete` 또는 `rejected`로 구분합니다. 과거 진입 근거가 없다고 현재 모델을 그 거래의 진입 모델로 채워 넣지 않습니다.

`stable_read`는 최대 3번 시도하며 연속 두 번 동일하게 읽힌 스냅샷을 사용합니다. 입력은 최대 32MiB이고 중복 JSON 키·비유한 숫자·링크·reparse·하드링크 등 허용하지 않는 입력을 거부합니다. 기본 입력 `work/paper/state.json`에서 읽고 기본 출력 `10차/work/trade-diagnostics.json`에 UTF-8 임시 파일·fsync·원자 교체로 저장합니다. 완전한 진단만 종료 코드 0이며 그 밖의 결과는 2입니다.

기존 누적 계좌의 매도 35건은 모두 DOGE였고 양수 1건·음수 34건, 순손익 -440,917.75원, 수수료 43,529.44원으로 집계되었습니다. 이 누적 장부와 10차 새 후보의 거래 0회 결과는 별개입니다. 과거 71건의 모델 메타데이터 누락도 장부 진단의 한계로 남습니다.

기본 `engine.py`의 `drawdown_limit`은 기본 0.1을 사용하며 bool·비유한 값·0 이하·1 이상을 거부합니다. `Portfolio` 복원은 초기 원금·모의 전용 표시·음수 잔액·고점·MDD·중지 기록을 검증합니다. `observe_drawdown`은 평가 고점과 현재·최대 낙폭을 갱신하고 한도 도달 시 `drawdown_halt`와 최초 시각을 보존합니다. 날짜 변경은 일일 매수 차단만 초기화하므로 최대 낙폭 차단은 해제되지 않습니다.

`Portfolio.process`는 같은 봉을 중복 처리하지 않으며 매수 전에도 낙폭을 확인합니다. 차단 중에도 손절·익절·만료·매도 신호 처리는 유지합니다. `clean_context`는 확률 3개·신호·유한 숫자·문자열 길이·시간봉을 검증하고 기존 `invalid`·`partial_invalid` 표시를 유지합니다. 매도 기록은 진입 당시 `entry_context`, 현재 `decision_context`, 실제/합성 호가·시각·비용의 `execution_context`를 나눕니다. 잘못된 진입 근거는 `entry_context_invalid=true`와 `entry_model_run=null`로 남겨 정상 근거처럼 재분류하지 않습니다.

**함수:** `fold_plans`

**맡은 처리와 경계:** 시장별 완료 봉에서 특징과 목표값을 구성하고 기존 모델의 학습 노출 범위, 제외 구간, 실제 행 수를 기록합니다.

**항목:** 기준시각

**10차 설정:** `2026-10-31T08:00:00Z`

**항목:** 구간 수·기간

**10차 설정:** 2개 구간, 학습 90일, 튜닝 2일, 정책 선택 2일, 후속 평가 2일

**항목:** 예측 지평

**10차 설정:** 5분봉 12개

**항목:** 모델

**10차 설정:** 최대 150회, 조기 종료 20회, 깊이 3, 학습률 0.05, `hist`, `cuda:0`, max_bin 128

**항목:** 반복 조건

**10차 설정:** seed 42, nthread 4, subsample·colsample_bytree 0.9, 최근 자료 가중치 반감기 30일

**항목:** 데이터 상한

**10차 설정:** 학습 100,000행, 원시 입력 300,000행, 분할 최소 100행

**항목:** 채택 조건

**10차 설정:** 구간별 최소 3회, 전체 최소 20회, 구간별 양의 순수익, MDD 0.1 이하

**항목:** 실행 보호

**10차 설정:** 최대 7,200초, 최소 여유 공간 20,000,000,000바이트


입력은 완료된 Upbit 5개 시장·9개 시간봉입니다. 이 실험은 4차의 외부 자료 50GB 기초학습을 수행한 결과가 아닙니다. 두 구간의 학습 창은 겹치므로 서로 독립된 두 연구의 성공으로 합산하지 않습니다.

설정 검증은 folds 1~2, rounds 2~150, early_stopping_rounds 2~20, depth 1~6, learning_rate 0.001~0.05를 허용합니다. 학습 행 상한은 100~100,000, 원시 행 상한은 1,000~300,000, 최소 분할 행은 100~100,000 범위입니다. 최소 구간 거래 수는 3~1,000, 총 거래 수는 20~10,000, max_drawdown은 0.001~0.1, max_seconds는 1~7,200, min_free_bytes는 20,000,000,000~1,000,000,000,000입니다.

누락 키에는 기본값을 합치되 학습·튜닝·정책·평가 기간과 horizon은 동결값과 같아야 합니다. folds=1은 입력으로 가능해도 최종 연구 검토의 두 구간 조건을 통과하지 못합니다.

정책은 일반 기대수익 방식과 불확실성 벌점 방식으로 나뉩니다. 벌점 계수는 0.25·0.5·1, 최소 순수익 기준은 0·0.0005·0.001이며 수수료·슬리피지를 반영합니다. 정책 선택 구간의 최고 수치와 후속 평가 수치를 섞지 않습니다.

`return_signals`는 비용 스트레스 비율을 `(0, 1]`에서 검증하고 평균·q10·q90이 모두 유한하며 분위수 폭이 음수가 아니고 평균이 양수일 때만 매수 후보를 만듭니다. `평균 − 벌점 × 분위수 폭`이 최소 기준을 엄격히 넘으면 신호 2, 나머지는 중립 1입니다. 현금 정책은 모두 중립을 반환합니다. 정책 점수가 현금과 같아도 현금을 유지합니다.

#### LEVEL 3 · 실행 조건·저장·중단

학습 진입에는 Linux 환경과 명시적인 `allow_training` 허용이 필요합니다. 실행 이름은 영문·숫자·밑줄·하이픈 1~80자이며 `10차/work/runner.lock`으로 중복 실행을 막습니다. 이미 존재하는 실행 폴더는 덮어쓰거나 자동 재개하지 않습니다. 정지 신호, 제한 시간, 여유 공간을 점검하며 기존 9차의 중지 정책과 이번 유한 실행의 허용 범위를 구분합니다.

`10차/work/status.json`은 현재 진행을 담고 `10차/work/runs/<run>/`에는 `request.json`, `manifest.json`, 구간별 `fold-1/`·`fold-2/`가 생깁니다. 각 구간에는 `data.json`, `policy.json`, `predictions.json`, `report.json`, `<시장>-<목표>.ubj` 모델과 해시·재로딩 근거가 남습니다. 실패 시 실행 폴더의 `failure.json`에 오류 종류·메시지·traceback·argv·cwd·진행 수를 기록하고 상태를 `stopped` 또는 `error`로 끝냅니다. 자동 재시도·자동 승격은 하지 않습니다. 명령 진입점은 `--once`·`--run`을 필수로 받고 `--allow-training`으로 해당 유한 실행을 허용합니다. 기본 설정은 `10차/return-research-config.json`이며 실제 실행 환경의 `engine-config.json`과 기존 DB·모델이 필요합니다.

진행 단계는 `prepare → fit → policy → validation → complete`이며 구간·시장·목표·반복 수·손실·GPU 확인 상태가 갱신됩니다. `Status.update`는 `0 ≤ completed_fits ≤ fit_calls ≤ max_fits ≤ 30`과 승격 금지를 검사한 뒤 원자 저장합니다. `10차/work/STOP`, SIGTERM, SIGINT는 유한 실행의 정지 경로로 연결됩니다. 적합 수가 동결 계획의 `folds × 15`와 다르면 완료로 저장하지 않습니다.

#### LEVEL 3 · 보존된 실험 집계와 미채택 결과

`실험결과.json`은 기존 실행의 집계입니다. CUDA 모델 적합 30개와 완료 30개, 모델 재로딩 검증이 기록되어 있습니다. 모델별 실제 반복 수는 21~150회, 학습 행은 24,780~25,237행이며 산출물은 85개입니다. 이번 문서 정리에서 학습을 새로 실행한 수치가 아닙니다.

일반 기대수익·불확실성 벌점·선택 정책은 두 후속 평가 구간과 두 비용 조건에서 모두 거래 0회, 순수익 0, MDD 0입니다. 현금 보유가 유지되었고 거래 수 부족과 구간별 양의 수익 조건 미달로 후보가 채택되지 않았습니다. `promotion=false`를 수익성 검증 성공으로 해석하지 않습니다.

정책 선택 구간의 한 시도는 순수익 약 0.13266%, MDD 약 0.28992%였지만 위험 조정 점수는 약 -0.000123으로 현금의 0보다 낮았습니다. 이것은 후속 평가 성적이 아니라 정책을 고르는 앞 구간의 수치입니다.

추세 기준선의 후속 순수익은 첫 구간 기본 비용 약 -3.75632%·2배 비용 -3.81247%, 둘째 구간 -3.38267%·-3.98338%입니다. 기존 분류 모델의 소급 비교는 첫 구간 +0.68186%·+0.53065%, 둘째 구간 +0.37101%·-0.12923%이지만 해당 평가 기간에 대한 학습 노출이 있어 독립 표본외 성적으로 사용하지 않습니다.

#### LEVEL 3 · 장부 진단과 기본 엔진의 거래 근거

`diagnose`와 `_reconstruct`는 매수 수수료를 포함한 취득원가를 수량 비율로 나눠 부분 매도의 원가를 계산합니다. 추가 매수와 남은 보유 수량을 함께 추적하는 평균원가 방식이며 FIFO가 아닙니다. 원장 누락·잔액 불일치·형식 오류는 `incomplete` 또는 `rejected`로 구분합니다. 과거 진입 근거가 없다고 현재 모델을 그 거래의 진입 모델로 채워 넣지 않습니다.

`stable_read`는 최대 3번 시도하며 연속 두 번 동일하게 읽힌 스냅샷을 사용합니다. 입력은 최대 32MiB이고 중복 JSON 키·비유한 숫자·링크·reparse·하드링크 등 허용하지 않는 입력을 거부합니다. 기본 입력 `work/paper/state.json`에서 읽고 기본 출력 `10차/work/trade-diagnostics.json`에 UTF-8 임시 파일·fsync·원자 교체로 저장합니다. 완전한 진단만 종료 코드 0이며 그 밖의 결과는 2입니다.

기존 누적 계좌의 매도 35건은 모두 DOGE였고 양수 1건·음수 34건, 순손익 -440,917.75원, 수수료 43,529.44원으로 집계되었습니다. 이 누적 장부와 10차 새 후보의 거래 0회 결과는 별개입니다. 과거 71건의 모델 메타데이터 누락도 장부 진단의 한계로 남습니다.

기본 `engine.py`의 `drawdown_limit`은 기본 0.1을 사용하며 bool·비유한 값·0 이하·1 이상을 거부합니다. `Portfolio` 복원은 초기 원금·모의 전용 표시·음수 잔액·고점·MDD·중지 기록을 검증합니다. `observe_drawdown`은 평가 고점과 현재·최대 낙폭을 갱신하고 한도 도달 시 `drawdown_halt`와 최초 시각을 보존합니다. 날짜 변경은 일일 매수 차단만 초기화하므로 최대 낙폭 차단은 해제되지 않습니다.

`Portfolio.process`는 같은 봉을 중복 처리하지 않으며 매수 전에도 낙폭을 확인합니다. 차단 중에도 손절·익절·만료·매도 신호 처리는 유지합니다. `clean_context`는 확률 3개·신호·유한 숫자·문자열 길이·시간봉을 검증하고 기존 `invalid`·`partial_invalid` 표시를 유지합니다. 매도 기록은 진입 당시 `entry_context`, 현재 `decision_context`, 실제/합성 호가·시각·비용의 `execution_context`를 나눕니다. 잘못된 진입 근거는 `entry_context_invalid=true`와 `entry_model_run=null`로 남겨 정상 근거처럼 재분류하지 않습니다.

#### LEVEL 4 · 수익률 연구의 모듈과 처리 순서

10차는 평균 수익률과 하위·상위 분위수를 함께 추정하고, 거래 비용과 낙폭을 반영한 정책을 현금 보유와 비교합니다.

`return_research.py`는 유한한 두 평가 구간을 실행하는 연구 도구이며, `trade_diagnostics.py`는 기존 모의계좌 장부의 매수·매도 연결과 손익을 읽는 별도 도구입니다.

**함수:** `validate_settings`

**맡은 처리와 경계:** 알 수 없는 설정 키, 잘못된 정수 범위, bool을 숫자로 넣은 값, 유한하지 않은 값을 거부합니다. 고정한 기간·예측 지평도 검사합니다.

**함수:** `fold_plans`

**맡은 처리와 경계:** 완료된 5분봉 기준시각에서 두 구간을 만들고 학습·튜닝·정책 선택·후속 평가 시간을 순서대로 분리합니다.

**함수:** `prepare_fold`

**맡은 처리와 경계:** 시장별 완료 봉에서 특징과 목표값을 구성하고 기존 모델의 학습 노출 범위, 제외 구간, 실제 행 수를 기록합니다.

**함수:** `fit_return_model`

**맡은 처리와 경계:** 시장·구간마다 평균, q10, q90 모델을 CUDA로 적합합니다. 평균은 제곱오차, 분위수는 0.1·0.9 분위수 손실을 사용합니다.

**함수:** `save_verified_model`

**맡은 처리와 경계:** UBJ 모델을 저장하고 다시 읽어 예측과 모델 해시를 대조합니다. 파일 생성과 재로딩 검증을 구분해 기록합니다.

**함수:** `select_policies`

**맡은 처리와 경계:** 정책 선택 구간에서 최소 거래 수·양의 순수익·낙폭 한도를 통과한 정책을 `순수익률 − 0.5 × MDD`로 비교합니다. 현금 점수 0을 넘지 못하면 거래 정책을 선택하지 않습니다.

**함수:** `review_eligibility`

**맡은 처리와 경계:** 선택에 쓰지 않은 후속 두 구간을 기본 비용과 2배 비용으로 평가하고 거래 수·구간별 수익·MDD 조건을 판정합니다.

**함수:** `run_study`

**맡은 처리와 경계:** 요청·진행·모델·구간 결과·최종 해시 목록을 저장합니다. 결과와 별개로 자동 승격을 수행하지 않습니다.


#### LEVEL 4 · 설정값과 입력 자료

**항목:** 기준시각

**10차 설정:** `2026-10-31T08:00:00Z`

**항목:** 구간 수·기간

**10차 설정:** 2개 구간, 학습 90일, 튜닝 2일, 정책 선택 2일, 후속 평가 2일

**항목:** 예측 지평

**10차 설정:** 5분봉 12개

**항목:** 모델

**10차 설정:** 최대 150회, 조기 종료 20회, 깊이 3, 학습률 0.05, `hist`, `cuda:0`, max_bin 128

**항목:** 반복 조건

**10차 설정:** seed 42, nthread 4, subsample·colsample_bytree 0.9, 최근 자료 가중치 반감기 30일

**항목:** 데이터 상한

**10차 설정:** 학습 100,000행, 원시 입력 300,000행, 분할 최소 100행

**항목:** 채택 조건

**10차 설정:** 구간별 최소 3회, 전체 최소 20회, 구간별 양의 순수익, MDD 0.1 이하

**항목:** 실행 보호

**10차 설정:** 최대 7,200초, 최소 여유 공간 20,000,000,000바이트


입력은 완료된 Upbit 5개 시장·9개 시간봉입니다. 이 실험은 4차의 외부 자료 50GB 기초학습을 수행한 결과가 아닙니다. 두 구간의 학습 창은 겹치므로 서로 독립된 두 연구의 성공으로 합산하지 않습니다.

설정 검증은 folds 1~2, rounds 2~150, early_stopping_rounds 2~20, depth 1~6, learning_rate 0.001~0.05를 허용합니다. 학습 행 상한은 100~100,000, 원시 행 상한은 1,000~300,000, 최소 분할 행은 100~100,000 범위입니다. 최소 구간 거래 수는 3~1,000, 총 거래 수는 20~10,000, max_drawdown은 0.001~0.1, max_seconds는 1~7,200, min_free_bytes는 20,000,000,000~1,000,000,000,000입니다.

누락 키에는 기본값을 합치되 학습·튜닝·정책·평가 기간과 horizon은 동결값과 같아야 합니다. folds=1은 입력으로 가능해도 최종 연구 검토의 두 구간 조건을 통과하지 못합니다.

정책은 일반 기대수익 방식과 불확실성 벌점 방식으로 나뉩니다. 벌점 계수는 0.25·0.5·1, 최소 순수익 기준은 0·0.0005·0.001이며 수수료·슬리피지를 반영합니다. 정책 선택 구간의 최고 수치와 후속 평가 수치를 섞지 않습니다.

`return_signals`는 비용 스트레스 비율을 `(0, 1]`에서 검증하고 평균·q10·q90이 모두 유한하며 분위수 폭이 음수가 아니고 평균이 양수일 때만 매수 후보를 만듭니다. `평균 − 벌점 × 분위수 폭`이 최소 기준을 엄격히 넘으면 신호 2, 나머지는 중립 1입니다. 현금 정책은 모두 중립을 반환합니다. 정책 점수가 현금과 같아도 현금을 유지합니다.

#### LEVEL 4 · 실행 조건·저장·중단

학습 진입에는 Linux 환경과 명시적인 `allow_training` 허용이 필요합니다. 실행 이름은 영문·숫자·밑줄·하이픈 1~80자이며 `10차/work/runner.lock`으로 중복 실행을 막습니다. 이미 존재하는 실행 폴더는 덮어쓰거나 자동 재개하지 않습니다. 정지 신호, 제한 시간, 여유 공간을 점검하며 기존 9차의 중지 정책과 이번 유한 실행의 허용 범위를 구분합니다.

`10차/work/status.json`은 현재 진행을 담고 `10차/work/runs/<run>/`에는 `request.json`, `manifest.json`, 구간별 `fold-1/`·`fold-2/`가 생깁니다. 각 구간에는 `data.json`, `policy.json`, `predictions.json`, `report.json`, `<시장>-<목표>.ubj` 모델과 해시·재로딩 근거가 남습니다. 실패 시 실행 폴더의 `failure.json`에 오류 종류·메시지·traceback·argv·cwd·진행 수를 기록하고 상태를 `stopped` 또는 `error`로 끝냅니다. 자동 재시도·자동 승격은 하지 않습니다. 명령 진입점은 `--once`·`--run`을 필수로 받고 `--allow-training`으로 해당 유한 실행을 허용합니다. 기본 설정은 `10차/return-research-config.json`이며 실제 실행 환경의 `engine-config.json`과 기존 DB·모델이 필요합니다.

진행 단계는 `prepare → fit → policy → validation → complete`이며 구간·시장·목표·반복 수·손실·GPU 확인 상태가 갱신됩니다. `Status.update`는 `0 ≤ completed_fits ≤ fit_calls ≤ max_fits ≤ 30`과 승격 금지를 검사한 뒤 원자 저장합니다. `10차/work/STOP`, SIGTERM, SIGINT는 유한 실행의 정지 경로로 연결됩니다. 적합 수가 동결 계획의 `folds × 15`와 다르면 완료로 저장하지 않습니다.

#### LEVEL 4 · 보존된 실험 집계와 미채택 결과

`실험결과.json`은 기존 실행의 집계입니다. CUDA 모델 적합 30개와 완료 30개, 모델 재로딩 검증이 기록되어 있습니다. 모델별 실제 반복 수는 21~150회, 학습 행은 24,780~25,237행이며 산출물은 85개입니다. 이번 문서 정리에서 학습을 새로 실행한 수치가 아닙니다.

일반 기대수익·불확실성 벌점·선택 정책은 두 후속 평가 구간과 두 비용 조건에서 모두 거래 0회, 순수익 0, MDD 0입니다. 현금 보유가 유지되었고 거래 수 부족과 구간별 양의 수익 조건 미달로 후보가 채택되지 않았습니다. `promotion=false`를 수익성 검증 성공으로 해석하지 않습니다.

정책 선택 구간의 한 시도는 순수익 약 0.13266%, MDD 약 0.28992%였지만 위험 조정 점수는 약 -0.000123으로 현금의 0보다 낮았습니다. 이것은 후속 평가 성적이 아니라 정책을 고르는 앞 구간의 수치입니다.

추세 기준선의 후속 순수익은 첫 구간 기본 비용 약 -3.75632%·2배 비용 -3.81247%, 둘째 구간 -3.38267%·-3.98338%입니다. 기존 분류 모델의 소급 비교는 첫 구간 +0.68186%·+0.53065%, 둘째 구간 +0.37101%·-0.12923%이지만 해당 평가 기간에 대한 학습 노출이 있어 독립 표본외 성적으로 사용하지 않습니다.

#### LEVEL 4 · 장부 진단과 기본 엔진의 거래 근거

`diagnose`와 `_reconstruct`는 매수 수수료를 포함한 취득원가를 수량 비율로 나눠 부분 매도의 원가를 계산합니다. 추가 매수와 남은 보유 수량을 함께 추적하는 평균원가 방식이며 FIFO가 아닙니다. 원장 누락·잔액 불일치·형식 오류는 `incomplete` 또는 `rejected`로 구분합니다. 과거 진입 근거가 없다고 현재 모델을 그 거래의 진입 모델로 채워 넣지 않습니다.

`stable_read`는 최대 3번 시도하며 연속 두 번 동일하게 읽힌 스냅샷을 사용합니다. 입력은 최대 32MiB이고 중복 JSON 키·비유한 숫자·링크·reparse·하드링크 등 허용하지 않는 입력을 거부합니다. 기본 입력 `work/paper/state.json`에서 읽고 기본 출력 `10차/work/trade-diagnostics.json`에 UTF-8 임시 파일·fsync·원자 교체로 저장합니다. 완전한 진단만 종료 코드 0이며 그 밖의 결과는 2입니다.

기존 누적 계좌의 매도 35건은 모두 DOGE였고 양수 1건·음수 34건, 순손익 -440,917.75원, 수수료 43,529.44원으로 집계되었습니다. 이 누적 장부와 10차 새 후보의 거래 0회 결과는 별개입니다. 과거 71건의 모델 메타데이터 누락도 장부 진단의 한계로 남습니다.

기본 `engine.py`의 `drawdown_limit`은 기본 0.1을 사용하며 bool·비유한 값·0 이하·1 이상을 거부합니다. `Portfolio` 복원은 초기 원금·모의 전용 표시·음수 잔액·고점·MDD·중지 기록을 검증합니다. `observe_drawdown`은 평가 고점과 현재·최대 낙폭을 갱신하고 한도 도달 시 `drawdown_halt`와 최초 시각을 보존합니다. 날짜 변경은 일일 매수 차단만 초기화하므로 최대 낙폭 차단은 해제되지 않습니다.

`Portfolio.process`는 같은 봉을 중복 처리하지 않으며 매수 전에도 낙폭을 확인합니다. 차단 중에도 손절·익절·만료·매도 신호 처리는 유지합니다. `clean_context`는 확률 3개·신호·유한 숫자·문자열 길이·시간봉을 검증하고 기존 `invalid`·`partial_invalid` 표시를 유지합니다. 매도 기록은 진입 당시 `entry_context`, 현재 `decision_context`, 실제/합성 호가·시각·비용의 `execution_context`를 나눕니다. 잘못된 진입 근거는 `entry_context_invalid=true`와 `entry_model_run=null`로 남겨 정상 근거처럼 재분류하지 않습니다.

## 수익률 연구의 모듈과 처리 순서

10차는 평균 수익률과 하위·상위 분위수를 함께 추정하고, 거래 비용과 낙폭을 반영한 정책을 현금 보유와 비교합니다.

`return_research.py`는 유한한 두 평가 구간을 실행하는 연구 도구이며, `trade_diagnostics.py`는 기존 모의계좌 장부의 매수·매도 연결과 손익을 읽는 별도 도구입니다.

**함수:** `validate_settings`

**맡은 처리와 경계:** 알 수 없는 설정 키, 잘못된 정수 범위, bool을 숫자로 넣은 값, 유한하지 않은 값을 거부합니다. 고정한 기간·예측 지평도 검사합니다.

**함수:** `fold_plans`

**맡은 처리와 경계:** 완료된 5분봉 기준시각에서 두 구간을 만들고 학습·튜닝·정책 선택·후속 평가 시간을 순서대로 분리합니다.

**함수:** `prepare_fold`

**맡은 처리와 경계:** 시장별 완료 봉에서 특징과 목표값을 구성하고 기존 모델의 학습 노출 범위, 제외 구간, 실제 행 수를 기록합니다.

**함수:** `fit_return_model`

**맡은 처리와 경계:** 시장·구간마다 평균, q10, q90 모델을 CUDA로 적합합니다. 평균은 제곱오차, 분위수는 0.1·0.9 분위수 손실을 사용합니다.

**함수:** `save_verified_model`

**맡은 처리와 경계:** UBJ 모델을 저장하고 다시 읽어 예측과 모델 해시를 대조합니다. 파일 생성과 재로딩 검증을 구분해 기록합니다.

**함수:** `select_policies`

**맡은 처리와 경계:** 정책 선택 구간에서 최소 거래 수·양의 순수익·낙폭 한도를 통과한 정책을 `순수익률 − 0.5 × MDD`로 비교합니다. 현금 점수 0을 넘지 못하면 거래 정책을 선택하지 않습니다.

**함수:** `review_eligibility`

**맡은 처리와 경계:** 선택에 쓰지 않은 후속 두 구간을 기본 비용과 2배 비용으로 평가하고 거래 수·구간별 수익·MDD 조건을 판정합니다.

**함수:** `run_study`

**맡은 처리와 경계:** 요청·진행·모델·구간 결과·최종 해시 목록을 저장합니다. 결과와 별개로 자동 승격을 수행하지 않습니다.

### 설정값과 입력 자료

**항목:** 기준시각

**10차 설정:** `2026-10-31T08:00:00Z`

**항목:** 구간 수·기간

**10차 설정:** 2개 구간, 학습 90일, 튜닝 2일, 정책 선택 2일, 후속 평가 2일

**항목:** 예측 지평

**10차 설정:** 5분봉 12개

**항목:** 모델

**10차 설정:** 최대 150회, 조기 종료 20회, 깊이 3, 학습률 0.05, `hist`, `cuda:0`, max_bin 128

**항목:** 반복 조건

**10차 설정:** seed 42, nthread 4, subsample·colsample_bytree 0.9, 최근 자료 가중치 반감기 30일

**항목:** 데이터 상한

**10차 설정:** 학습 100,000행, 원시 입력 300,000행, 분할 최소 100행

**항목:** 채택 조건

**10차 설정:** 구간별 최소 3회, 전체 최소 20회, 구간별 양의 순수익, MDD 0.1 이하

**항목:** 실행 보호

**10차 설정:** 최대 7,200초, 최소 여유 공간 20,000,000,000바이트


입력은 완료된 Upbit 5개 시장·9개 시간봉입니다. 이 실험은 4차의 외부 자료 50GB 기초학습을 수행한 결과가 아닙니다. 두 구간의 학습 창은 겹치므로 서로 독립된 두 연구의 성공으로 합산하지 않습니다.

설정 검증은 folds 1~2, rounds 2~150, early_stopping_rounds 2~20, depth 1~6, learning_rate 0.001~0.05를 허용합니다. 학습 행 상한은 100~100,000, 원시 행 상한은 1,000~300,000, 최소 분할 행은 100~100,000 범위입니다. 최소 구간 거래 수는 3~1,000, 총 거래 수는 20~10,000, max_drawdown은 0.001~0.1, max_seconds는 1~7,200, min_free_bytes는 20,000,000,000~1,000,000,000,000입니다.

누락 키에는 기본값을 합치되 학습·튜닝·정책·평가 기간과 horizon은 동결값과 같아야 합니다. folds=1은 입력으로 가능해도 최종 연구 검토의 두 구간 조건을 통과하지 못합니다.

정책은 일반 기대수익 방식과 불확실성 벌점 방식으로 나뉩니다. 벌점 계수는 0.25·0.5·1, 최소 순수익 기준은 0·0.0005·0.001이며 수수료·슬리피지를 반영합니다. 정책 선택 구간의 최고 수치와 후속 평가 수치를 섞지 않습니다.

`return_signals`는 비용 스트레스 비율을 `(0, 1]`에서 검증하고 평균·q10·q90이 모두 유한하며 분위수 폭이 음수가 아니고 평균이 양수일 때만 매수 후보를 만듭니다. `평균 − 벌점 × 분위수 폭`이 최소 기준을 엄격히 넘으면 신호 2, 나머지는 중립 1입니다. 현금 정책은 모두 중립을 반환합니다. 정책 점수가 현금과 같아도 현금을 유지합니다.

<a name="usage"></a>

### 실행 조건·저장·중단

학습 진입에는 Linux 환경과 명시적인 `allow_training` 허용이 필요합니다. 실행 이름은 영문·숫자·밑줄·하이픈 1~80자이며 `10차/work/runner.lock`으로 중복 실행을 막습니다. 이미 존재하는 실행 폴더는 덮어쓰거나 자동 재개하지 않습니다. 정지 신호, 제한 시간, 여유 공간을 점검하며 기존 9차의 중지 정책과 이번 유한 실행의 허용 범위를 구분합니다.

`10차/work/status.json`은 현재 진행을 담고 `10차/work/runs/<run>/`에는 `request.json`, `manifest.json`, 구간별 `fold-1/`·`fold-2/`가 생깁니다. 각 구간에는 `data.json`, `policy.json`, `predictions.json`, `report.json`, `<시장>-<목표>.ubj` 모델과 해시·재로딩 근거가 남습니다. 실패 시 실행 폴더의 `failure.json`에 오류 종류·메시지·traceback·argv·cwd·진행 수를 기록하고 상태를 `stopped` 또는 `error`로 끝냅니다. 자동 재시도·자동 승격은 하지 않습니다. 명령 진입점은 `--once`·`--run`을 필수로 받고 `--allow-training`으로 해당 유한 실행을 허용합니다. 기본 설정은 `10차/return-research-config.json`이며 실제 실행 환경의 `engine-config.json`과 기존 DB·모델이 필요합니다.

진행 단계는 `prepare → fit → policy → validation → complete`이며 구간·시장·목표·반복 수·손실·GPU 확인 상태가 갱신됩니다. `Status.update`는 `0 ≤ completed_fits ≤ fit_calls ≤ max_fits ≤ 30`과 승격 금지를 검사한 뒤 원자 저장합니다. `10차/work/STOP`, SIGTERM, SIGINT는 유한 실행의 정지 경로로 연결됩니다. 적합 수가 동결 계획의 `folds × 15`와 다르면 완료로 저장하지 않습니다.

## 보존된 실험 집계와 미채택 결과

`실험결과.json`은 기존 실행의 집계입니다. CUDA 모델 적합 30개와 완료 30개, 모델 재로딩 검증이 기록되어 있습니다. 모델별 실제 반복 수는 21~150회, 학습 행은 24,780~25,237행이며 산출물은 85개입니다. 이번 문서 정리에서 학습을 새로 실행한 수치가 아닙니다.

일반 기대수익·불확실성 벌점·선택 정책은 두 후속 평가 구간과 두 비용 조건에서 모두 거래 0회, 순수익 0, MDD 0입니다. 현금 보유가 유지되었고 거래 수 부족과 구간별 양의 수익 조건 미달로 후보가 채택되지 않았습니다. `promotion=false`를 수익성 검증 성공으로 해석하지 않습니다.

정책 선택 구간의 한 시도는 순수익 약 0.13266%, MDD 약 0.28992%였지만 위험 조정 점수는 약 -0.000123으로 현금의 0보다 낮았습니다. 이것은 후속 평가 성적이 아니라 정책을 고르는 앞 구간의 수치입니다.

추세 기준선의 후속 순수익은 첫 구간 기본 비용 약 -3.75632%·2배 비용 -3.81247%, 둘째 구간 -3.38267%·-3.98338%입니다. 기존 분류 모델의 소급 비교는 첫 구간 +0.68186%·+0.53065%, 둘째 구간 +0.37101%·-0.12923%이지만 해당 평가 기간에 대한 학습 노출이 있어 독립 표본외 성적으로 사용하지 않습니다.

## 장부 진단과 기본 엔진의 거래 근거

`diagnose`와 `_reconstruct`는 매수 수수료를 포함한 취득원가를 수량 비율로 나눠 부분 매도의 원가를 계산합니다. 추가 매수와 남은 보유 수량을 함께 추적하는 평균원가 방식이며 FIFO가 아닙니다. 원장 누락·잔액 불일치·형식 오류는 `incomplete` 또는 `rejected`로 구분합니다. 과거 진입 근거가 없다고 현재 모델을 그 거래의 진입 모델로 채워 넣지 않습니다.

`stable_read`는 최대 3번 시도하며 연속 두 번 동일하게 읽힌 스냅샷을 사용합니다. 입력은 최대 32MiB이고 중복 JSON 키·비유한 숫자·링크·reparse·하드링크 등 허용하지 않는 입력을 거부합니다. 기본 입력 `work/paper/state.json`에서 읽고 기본 출력 `10차/work/trade-diagnostics.json`에 UTF-8 임시 파일·fsync·원자 교체로 저장합니다. 완전한 진단만 종료 코드 0이며 그 밖의 결과는 2입니다.

기존 누적 계좌의 매도 35건은 모두 DOGE였고 양수 1건·음수 34건, 순손익 -440,917.75원, 수수료 43,529.44원으로 집계되었습니다. 이 누적 장부와 10차 새 후보의 거래 0회 결과는 별개입니다. 과거 71건의 모델 메타데이터 누락도 장부 진단의 한계로 남습니다.

기본 `engine.py`의 `drawdown_limit`은 기본 0.1을 사용하며 bool·비유한 값·0 이하·1 이상을 거부합니다. `Portfolio` 복원은 초기 원금·모의 전용 표시·음수 잔액·고점·MDD·중지 기록을 검증합니다. `observe_drawdown`은 평가 고점과 현재·최대 낙폭을 갱신하고 한도 도달 시 `drawdown_halt`와 최초 시각을 보존합니다. 날짜 변경은 일일 매수 차단만 초기화하므로 최대 낙폭 차단은 해제되지 않습니다.

`Portfolio.process`는 같은 봉을 중복 처리하지 않으며 매수 전에도 낙폭을 확인합니다. 차단 중에도 손절·익절·만료·매도 신호 처리는 유지합니다. `clean_context`는 확률 3개·신호·유한 숫자·문자열 길이·시간봉을 검증하고 기존 `invalid`·`partial_invalid` 표시를 유지합니다. 매도 기록은 진입 당시 `entry_context`, 현재 `decision_context`, 실제/합성 호가·시각·비용의 `execution_context`를 나눕니다. 잘못된 진입 근거는 `entry_context_invalid=true`와 `entry_model_run=null`로 남겨 정상 근거처럼 재분류하지 않습니다.
