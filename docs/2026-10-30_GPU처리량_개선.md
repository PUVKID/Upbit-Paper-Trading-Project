# GPU 처리량 개선

## 요구와 확인

2026-10-30 사용자는 낮은 GPU 사용률의 원인을 해결하고 더 많은 실제 데이터를 통합해 실험하기를 요청했습니다. 유용한 학습 처리량을 높이는 작업이며 GPU100% 표시를 목표로 무의미한 계산을 추가하지 않습니다. 현재 5개 코인·9개 시간봉·약344만 학습 행을 사용하며 한 번에 읽는 자료에는 기존 메모리 상한이 있습니다.

현재 코드는 코인별 특징 준비와 후보 학습을 직렬 처리하며 후보마다 같은 학습 행렬을 재생성합니다. 실제 완료 한 회차는978.63초, 15개 학습 호출 시간 합계는 약88초입니다. 이 차이가 전부 특징 준비 시간이라는 뜻은 아니며 DB조회·분할·평가·저장 등 비학습 작업을 포함합니다. 당시 features 단계 장치 전체 사용률20%, 메모리5020/24564MiB,53도였습니다. 다른 연구 작업도 실행 중이므로 이 수치를 본 프로젝트의 독점 사용량으로 해석하지 않습니다.

실제 SQLite 조회 계획은 close_time 인덱스 조회 뒤 open_time 임시 정렬이 발생합니다. 고정 시간봉에서는 완료 시각과 시작 시각의 순서가 같으며 정렬 최적화도 반환 행·범위·제한 수의 동일성을 검사해야 합니다.

## 변경 계획과 성공 조건

1. 기존 엔진을 소스만 보존하고 실제 데이터 기준 측정을 남깁니다. 운영 DB는 Linux에서만 엽니다.
2. 같은 코인의 후보들은 학습 행렬을 재사용하고 특징 준비의 유한 선행 처리를 검토합니다. 현재 모델과 모든 후보의 설정·학습 자료·조기 종료·CPU 대체 금지 검사는 유지합니다.
3. DB 정렬 전후 반환 결과·시간과 학습 준비·적합 시간을 구분합니다. 최대 메모리와 실패 전파·시점 분리 회귀를 검증합니다.
4. 전체 회귀·정적 검사 및 독립 검증 뒤 다음 정규 학습 회차에 적용합니다. 공유 컨테이너 재시작이나 계좌 초기화, 거래 강제는 하지 않습니다.
5. 공개용 변경 기록과 실제 차이만 기존 저장소에 반영합니다. 데이터·장부·모델·개인 지침·운영 로그는 공개하지 않습니다.

특징 준비에는 CPU·저장장치가 필요하며 높은 GPU 사용률이 높은 수익이나95% 정확도를 보장하지 않습니다. 계속 학습과 모의매매는 별도 서비스로 유지합니다.

## 전체 자료와 평가 자료

수집된 시간봉을 함께 결합하는 것과 학습·시험 구간을 섞는 것은 다릅니다. 시간순 학습·튜닝·확률 보정·정책 선정·후속 평가와 이미 소비된 잠금 시험 보호는 유지합니다. 한 번의 API 호출로 모든 과거 데이터를 받는 기능은 없으며 최대200개 응답을 커서로 이어 수집합니다. 요청 제한은 IP당 캔들 그룹 합계초당10회이며 기존 안전 간격은 유지합니다. 이미 저장된 완료 봉은 다시 덮어쓰지 않습니다.

## 실측 결과

부분 SQL 비교는 같은2만행 반환140.645초→0.854초이며 결과가 동일합니다. 전체 비트코인9시간봉 특징 준비는273.397초→131.425초였습니다. 두 측정 사이 과거 자료 수집으로 학습 행이860307개에서861111개로 늘었고 캐시·공유 부하도 같지 않아 엄밀한 동일 입력 반복 실험이나 전체 회차 가속 배수로 해석하지 않습니다.

개선 시점의 동일861111학습 행·563튜닝 행·92특징으로 깊이3/5/7의80라운드를 비교하면 기존 학습 호출 합계12.309초, 행렬 재사용7.482초였습니다. 두 번째와 세 번째 후보는 행렬을 재사용했습니다. 학습률0.05·모든 모델 파라미터·조기 종료·평가 경계는 유지했습니다. GPU 수치 연산·행렬 캐시 때문에 완전히 같은 모델 파일을 보장하지 않으며 이후 검증과 승격 조건을 그대로 적용합니다. 운영 최대400라운드는 축소하지 않았고80라운드는 별도 처리량 비교에만 썼습니다.

적합 비교 구간의 장치 전체 NVML73시료는 평균50.0%·최대82%, 메모리 최대6666MiB였습니다. 이 구간은 기존/개선 비교를 모두 포함하며 본 프로젝트만의 점유율이나 하루 평균이 아닙니다. 준비 구간에는 GPU가 낮을 수 있고100%상시 사용은 달성했다고 보고하지 않습니다.

구현자 Linux 보충 전체 회귀212개는72.696초에 통과했고 기존 정적 검사는79개 통과했습니다. 이 보충 실행을 공식30초 제한의 검사 통과라고 기록하지 않으며 별도 검증자가 기존 공식 명세를 그대로 실행합니다. 최종 독립 검증 결과와 공개 반영은 별도 영수증에 기록합니다.
