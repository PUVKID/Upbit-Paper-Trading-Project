## 실제 변경

`CandleStore.read`는 완료 시각 범위 인덱스와 같은 순서로 조회해 임시 정렬을 제거합니다. 반환 행의 완료 시각 간격이 시간봉과 다르면 거부합니다. 기존 요청 범위·제한 수·최종 시작 시각 오름차순은 유지합니다.

`gpu_matrix_scope`는 같은 시장·같은 입력 객체·같은 열·같은 가중치 설정의 후보 묶음에서만 두 DMatrix를 재사용합니다. 범위 밖 호출과 다른 시장·가중치는 공유하지 않으며 종료 시 참조를 해제합니다. 해당 범위의 입력은 읽기 전용이며 제자리 변경은 지원하지 않습니다. 기존 CUDA 사전 검사와 매 반복 검사도 그대로 수행합니다.

`market_feature_loader`는 하나의 CPU 작업자로 다음 시장 특징만 선행 준비합니다. 누적 자료를 임의로 축소하지 않으며 학습·검증 범위는 같습니다. 준비 오류는 상위 호출로 전달하고, 본 작업 오류와 동시에 발생한 오류 원문도 예외에 남깁니다. 진행 중 SQL을 강제 종료하는 기능은 없습니다.

`train_cycle`에 두 범위를 연결하고 특징 준비·특징 대기·라벨/분할/감사·적합/예측·평가 시간을 별도 기록합니다. 선행 처리 시간은 겹치므로 항목들을 더해 전체 경과 시간으로 해석하면 안 됩니다. `fit_gpu`는 실제 파라미터와 행렬 재사용 여부·준비/사전 검사/적합 시간을 추가 기록합니다.

새 의존성·모델 후보·학습률·깊이·수수료·승격·실제 주문·알림은 추가하지 않았습니다. 큰 차이의 일부는 기존 시장 반복을 컨텍스트 내부로 옮긴 들여쓰기입니다. 전체 차이에는 주석·공백까지 포함합니다.

## 검증 범위

최종 [독립 검증 결과](gpu-throughput-20261030-verification.md)는 PASS입니다. 다음 새 차수 작업과 이번 검증 범위를 혼동하지 않습니다.

신규10회귀는 행렬 재사용·해제·다른 입력·CPU거부, 1개 선행 준비·동일 범위·오류 전파·스레드 종료, SQL 반환·손상 거부, 5시장15후보 전체 연결과 승격 보류를 검사합니다. Linux 전체212회귀와 정적 검사는 구현자 근거이며 독립 검증 결과는 별도 확인합니다. 통제된 대역 모델 검사는 실제 수익 검증이 아닙니다.

실제 시세 처리량 비교에는 별도80라운드를 사용했습니다. 부분SQL140.645초→0.854초, 비트코인 전체 특징 준비273.397초→131.425초, 같은 자료의3후보 적합12.309초→7.482초입니다. 시점별 자료 증가·캐시·동시 부하 및 GPU 비결정성이 있으므로 전체 운영 가속 배수·수익 개선으로 일반화하지 않습니다. 장치 전체 사용률은 해당 적합 비교 구간 평균50.0%·최대82%이며100%상시 점유를 달성한 것이 아닙니다.

## 공개 제외

운영 DB·계좌·모델·실험 원문·프로세스 로그·개인 지침·라우팅 영수증·압축 원본은 공개하지 않습니다. 공개 기록은 코드와 검사, 집계한 실측 결과만 포함합니다. 운영 손익이나 계좌 정보를 GPU 처리량의 근거로 올리지 않습니다. 로컬 반영 영수증에는 푸시 뒤 커밋과 원격 확인을 별도 기록합니다.
