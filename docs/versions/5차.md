## LEVEL 1 - Beginner

### LEVEL 1 · 이 자료가 하는 일과 달라진 점

### LEVEL 1 · 실제 동작을 따라 읽기

50GB 적재 뒤에도 최근14일 분봉 커버리지가 부족했던 월 경계 누락을 bootstrap_plan에서 보완합니다.

직전 월별 아카이브를 유지하고 이번 달·최근14일의 완료 UTC 날짜 일별 원본을 최근 순으로 요청합니다.

원래50GB/요청당2GB 두 트랙 연구 계약과98% 커버리지·최신성·GPU 전용·평가/승격 조건을 유지합니다.

체크섬은 받은 바이트가 형식상 손상되지 않았는지 대조하는 값입니다. 모의 운용은 계산상 계좌와 거래를 다루므로 실제 계좌 체결과 구분합니다.

입력 — 월 경계 원본 공개 지연과 실제 최근 분봉·적재량 관측

처리 — 3차/external_data.py의 날짜 계획 수정과 기존 검증 재사용

출력 — 5차 변경기록·전체비교와 자료 준비 재관측

#### LEVEL 1 · 이 차수 원래 안내의 세부 조건

#### LEVEL 1 · 확인한 원인

적재량은 50,236,121,507바이트였으나 다섯 종목 모두 최근 14일 분봉이 18,969개로, 기존 98% 기준인 19,756.8개에 미달했습니다. 확인한 BTC 누락 구간은 2026-10-31 03:57~23:47 UTC의 1,191분입니다. 이는 원본 체결 오류를 격리했던 4차의 문제와 다릅니다.

기존 준비 계획은 직전 월의 월별 아카이브와 현재 월의 일별 아카이브만 요청했습니다. 월별 원본 공개 지연·기존 수집 중단이 겹치면 전월 말의 일별 자료를 다시 확보할 경로가 없습니다. 최신 1,000개 분봉 조회도 이미 지나간 공백을 복구하지 못합니다.

#### LEVEL 1 · 수정

[활성 수집기](../../3%EC%B0%A8/external_data.py)의 `bootstrap_plan`에서 직전 월별 자료를 유지하면서, 이번 달 이력과 최근 14일에 해당하는 완료 UTC 날짜의 일별 원본을 요청합니다. 월·연도·윤년을 날짜 API로 처리하며 같은 파일은 한 계획에 한 번만 포함합니다. 최근 날짜부터 확인합니다.

기존 체크섬·내용 검증·완료봉·고유 저장을 재사용합니다. 50GB를 DB나 압축해제 용량으로 대체하지 않으며, 최근 14일 98% 커버리지·최신성·GPU 전용 적합·평가·승격 기준은 완화하지 않습니다. 이미 저장된 분봉을 덮어쓰거나 임의 보간하지 않습니다.

[회귀 검사](../../tests/test_recent_archive_plan.py)는 월 경계·연도 변경·윤년·현재 월 이력·중복 요청·완료 UTC 날짜와 다른 시간대 입력을 확인합니다. 실제 자료와 통제된 회귀 검사를 구분하며, 소프트웨어 검사 통과를 학습 성적이나 수익으로 해석하지 않습니다.

#### LEVEL 1 · 유지한 운용

#### LEVEL 1 · 검사와 한계

최초 회귀 3개에서 월 경계와 새해·윤년 두 검사가 실패했고, 수정 뒤 같은 검사가 통과했습니다. 시간대 경계 검사를 추가한 Linux 회귀 4개가 통과했습니다. 라이브러리의 날짜 비교 관련 폐기 예정 경고는 억제하지 않았으며 검사 실패나 학습 완료로 혼동하지 않습니다.

수집기 재실행은 기존 대용량 원본의 무결성을 다시 확인합니다. 새 PID나 소프트웨어 검사 통과만으로 누락 복구·GPU 학습 진입을 주장하지 않으며 실제 최근 분봉 수·준비 표시·학습 진행과 모의매매 갱신을 별도로 확인합니다. 학습 완료·승격·수익 개선은 각각 후속 결과가 있어야 판단합니다.

2026-11-02 10:41 한국 시각 실제 적재량 50,236,409,654바이트와 고유 분봉 7,673,485개에서 준비 표시가 참으로 바뀌었습니다. 초기 연구는 10:39 비트코인 특징 준비에 진입했습니다. 이 관측은 준비 검사 통과와 연구 시작이며 GPU 적합 완료나 성과 증거는 아닙니다. 같은 관측에서 모의매매 판단은 730회차, 정상 완료 누적 703회였습니다. 프로세스 회차와 실제 체결 수는 다릅니다.

#### LEVEL 1 · 연구 요청·저장·실패 복구

`validate_config`는 `active`·`continuous`·`state_path` 외 설정을 거부하고 두 플래그는 정확한 bool을 요구합니다. 기본값은 `active=false`, `continuous=false`, `state_path=4차/work/research_control.json`입니다. 경로는 프로젝트의 `4차/work` 안 JSON으로 제한하고, 비활성 상태의 연속 연구는 거부합니다. `continuous` 코드 분기가 존재해도 이 차수의 두 트랙 계약은 초기 완료 후 명시 요청 대기입니다.

`request_increment`는 초기 학습 미완료·기존 활성 요청을 거부합니다. 요청을 받은 시점의 실제 고유 적재량을 baseline으로 읽고 2,000,000,000바이트를 더한 목표를 저장하므로, 이전 아카이브 단위 초과분을 다음 요청 분량으로 재사용하지 않습니다.

**함수·상태:** `_read`·`_validate`

**동작과 경계:** 첫 상태는 schema_version=1, bootstrap·collecting입니다. batch 필드, 비음수 정수, UTC 시각, ID·상태·완료 근거를 검증하고 JSON 중복 키를 거부합니다.

**함수·상태:** `training_lock`·상태 잠금

**동작과 경계:** 긴 적합 점유와 짧은 상태 읽기 잠금을 분리합니다. 상태 잠금은 최대30초,50ms 간격이며 학습 잠금은 비차단입니다.

**함수·상태:** `claim_training`

**동작과 경계:** collecting만 training으로 바꾸고 UUID claim과 attempts+1을 저장합니다.

**함수·상태:** `start_attempt`

**동작과 경계:** 요청·claim·시도·목표와 결과 폴더를 묶은 별도 시도 JSON을 만들며 기존 시도를 덮지 않습니다.

**함수·상태:** `record_model_failure`

**동작과 경계:** running 시도를 model_failed로 남기고 batch를 collecting으로 돌립니다. 오류 원문·시도 횟수는 보존합니다.

**함수·상태:** `store_result`

**동작과 경계:** 보고서 SHA·manifest SHA·모델 SHA와 batch 결합을 확인하여 complete 시도 결과를 원자 저장합니다.

**함수·상태:** `restore_claim`·`complete_training`

**동작과 경계:** 저장된 complete 결과를 검증하여 소유권과 완료 상태를 복구합니다. 완료 결과가 있는 시도를 무조건 재학습하지 않습니다.


`_atomic_write`는 UTF-8·LF·NaN 금지 JSON을 임시 파일에 쓰고 flush/fsync 후 교체합니다. 상태·시도 파일의 심볼릭 링크를 거부합니다. `_result`는 BTC·SOL·ETH·XRP·DOGE 다섯 시장의 후보 수, `cuda:` 장치, 준비 참, 목표 이상의 고유 적재/검증 바이트를 대조합니다. `promoted`는 학습 완료와 별도 bool로 기록합니다.

<a name="-이-차수-원래-안내의-세부-조건"></a>
### 이 차수 원래 안내의 세부 조건

### 확인한 원인

적재량은 50,236,121,507바이트였으나 다섯 종목 모두 최근 14일 분봉이 18,969개로, 기존 98% 기준인 19,756.8개에 미달했습니다. 확인한 BTC 누락 구간은 2026-10-31 03:57~23:47 UTC의 1,191분입니다. 이는 원본 체결 오류를 격리했던 4차의 문제와 다릅니다.

기존 준비 계획은 직전 월의 월별 아카이브와 현재 월의 일별 아카이브만 요청했습니다. 월별 원본 공개 지연·기존 수집 중단이 겹치면 전월 말의 일별 자료를 다시 확보할 경로가 없습니다. 최신 1,000개 분봉 조회도 이미 지나간 공백을 복구하지 못합니다.

### 수정

[활성 수집기](../../3%EC%B0%A8/external_data.py)의 `bootstrap_plan`에서 직전 월별 자료를 유지하면서, 이번 달 이력과 최근 14일에 해당하는 완료 UTC 날짜의 일별 원본을 요청합니다. 월·연도·윤년을 날짜 API로 처리하며 같은 파일은 한 계획에 한 번만 포함합니다. 최근 날짜부터 확인합니다.

기존 체크섬·내용 검증·완료봉·고유 저장을 재사용합니다. 50GB를 DB나 압축해제 용량으로 대체하지 않으며, 최근 14일 98% 커버리지·최신성·GPU 전용 적합·평가·승격 기준은 완화하지 않습니다. 이미 저장된 분봉을 덮어쓰거나 임의 보간하지 않습니다.

[회귀 검사](../../tests/test_recent_archive_plan.py)는 월 경계·연도 변경·윤년·현재 월 이력·중복 요청·완료 UTC 날짜와 다른 시간대 입력을 확인합니다. 실제 자료와 통제된 회귀 검사를 구분하며, 소프트웨어 검사 통과를 학습 성적이나 수익으로 해석하지 않습니다.

### 유지한 운용

[4차 두 트랙 계약](../../4%EC%B0%A8/docs/%EB%91%90%ED%8A%B8%EB%9E%99_%EC%97%B0%EA%B5%AC%EA%B3%84%EC%95%BD.md)은 그대로입니다. 최초 50GB 준비 후 연구 한 회차를 수행하고, 완료 후 명시 요청을 기다립니다. 이후 요청마다 그 시점의 실제 적재량보다 새 고유 자료 2GB를 확보한 뒤 연구 한 회차를 수행합니다. 이번 재개가 새 2GB 요청을 추가하지는 않습니다.

모의매매와 최신 시세는 독립 트랙입니다. 수집기만 수정본으로 재실행했으며 감독 프로세스·모의매매·공유 컨테이너는 재시작하지 않았습니다. 원금 1,000만원과 기존 장부를 유지하고 실제 주문·외부 알림·강제 거래를 추가하지 않습니다.

### 검사와 한계

최초 회귀 3개에서 월 경계와 새해·윤년 두 검사가 실패했고, 수정 뒤 같은 검사가 통과했습니다. 시간대 경계 검사를 추가한 Linux 회귀 4개가 통과했습니다. 라이브러리의 날짜 비교 관련 폐기 예정 경고는 억제하지 않았으며 검사 실패나 학습 완료로 혼동하지 않습니다.

수집기 재실행은 기존 대용량 원본의 무결성을 다시 확인합니다. 새 PID나 소프트웨어 검사 통과만으로 누락 복구·GPU 학습 진입을 주장하지 않으며 실제 최근 분봉 수·준비 표시·학습 진행과 모의매매 갱신을 별도로 확인합니다. 학습 완료·승격·수익 개선은 각각 후속 결과가 있어야 판단합니다.

2026-11-02 10:41 한국 시각 실제 적재량 50,236,409,654바이트와 고유 분봉 7,673,485개에서 준비 표시가 참으로 바뀌었습니다. 초기 연구는 10:39 비트코인 특징 준비에 진입했습니다. 이 관측은 준비 검사 통과와 연구 시작이며 GPU 적합 완료나 성과 증거는 아닙니다. 같은 관측에서 모의매매 판단은 730회차, 정상 완료 누적 703회였습니다. 프로세스 회차와 실제 체결 수는 다릅니다.

### 연구 요청·저장·실패 복구

`validate_config`는 `active`·`continuous`·`state_path` 외 설정을 거부하고 두 플래그는 정확한 bool을 요구합니다. 기본값은 `active=false`, `continuous=false`, `state_path=4차/work/research_control.json`입니다. 경로는 프로젝트의 `4차/work` 안 JSON으로 제한하고, 비활성 상태의 연속 연구는 거부합니다. `continuous` 코드 분기가 존재해도 이 차수의 두 트랙 계약은 초기 완료 후 명시 요청 대기입니다.

`request_increment`는 초기 학습 미완료·기존 활성 요청을 거부합니다. 요청을 받은 시점의 실제 고유 적재량을 baseline으로 읽고 2,000,000,000바이트를 더한 목표를 저장하므로, 이전 아카이브 단위 초과분을 다음 요청 분량으로 재사용하지 않습니다.

**함수·상태:** `_read`·`_validate`

**동작과 경계:** 첫 상태는 schema_version=1, bootstrap·collecting입니다. batch 필드, 비음수 정수, UTC 시각, ID·상태·완료 근거를 검증하고 JSON 중복 키를 거부합니다.

**함수·상태:** `training_lock`·상태 잠금

**동작과 경계:** 긴 적합 점유와 짧은 상태 읽기 잠금을 분리합니다. 상태 잠금은 최대30초,50ms 간격이며 학습 잠금은 비차단입니다.

**함수·상태:** `claim_training`

**동작과 경계:** collecting만 training으로 바꾸고 UUID claim과 attempts+1을 저장합니다.

**함수·상태:** `start_attempt`

**동작과 경계:** 요청·claim·시도·목표와 결과 폴더를 묶은 별도 시도 JSON을 만들며 기존 시도를 덮지 않습니다.

**함수·상태:** `record_model_failure`

**동작과 경계:** running 시도를 model_failed로 남기고 batch를 collecting으로 돌립니다. 오류 원문·시도 횟수는 보존합니다.

**함수·상태:** `store_result`

**동작과 경계:** 보고서 SHA·manifest SHA·모델 SHA와 batch 결합을 확인하여 complete 시도 결과를 원자 저장합니다.

**함수·상태:** `restore_claim`·`complete_training`

**동작과 경계:** 저장된 complete 결과를 검증하여 소유권과 완료 상태를 복구합니다. 완료 결과가 있는 시도를 무조건 재학습하지 않습니다.


`_atomic_write`는 UTF-8·LF·NaN 금지 JSON을 임시 파일에 쓰고 flush/fsync 후 교체합니다. 상태·시도 파일의 심볼릭 링크를 거부합니다. `_result`는 BTC·SOL·ETH·XRP·DOGE 다섯 시장의 후보 수, `cuda:` 장치, 준비 참, 목표 이상의 고유 적재/검증 바이트를 대조합니다. `promoted`는 학습 완료와 별도 bool로 기록합니다.
