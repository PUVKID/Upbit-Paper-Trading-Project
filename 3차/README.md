# 3차 대용량 자료 학습

## 실행 순서

1. 외부 거래소의 고유 아카이브50GB를 다운로드하고SHA256검증·청크집계를 마칩니다.
2. 다섯 종목의 최신성·최근14일범위·실제 DB스키마·파일무결성까지 확인한 뒤GPU학습을 시작합니다.
3. 이후 업비트에서 요청당200개씩완성봉을 중복없이누적하며 재학습합니다. 외부특징에 필요한최신보조시세도 갱신합니다.
4. 기존 업비트 현물 모의계좌는 다운로드·학습과 별개로 계속 운용합니다. 새 모델은 기존 시간순검증·비용 차감손익·승격기준을 통과할 때만 적용됩니다.

가상 원금은기존합계1,000만원을 이어 사용합니다. 실제주문·인증키·레버리지·강제거래·외부알림은 없습니다. 100%정확도·수익·상시GPU100%를 보장하지 않습니다. 다운로드/처리에CPU와저장장치가필요하며학습전용CUDA검사는유지합니다.

## 구성

- `external_data.py`: 공식 월간/일간 캔들·체결파일 수집, 원본 SHA256검증, 스트리밍1분봉집계와실시간업데이트.
- `external_features.py`: 외부분봉실제schema검사·50GB학습시작조건·상대가격/거래흐름11개특징. 원화가격·업비트라벨과섞지않습니다.
- `manage.py`:3차수집기만시작·상태·정상정지합니다. 공용컨테이너나기존감독프로세스를재시작하지않습니다.
- `engine-config.json`:이번차수설정스냅숏. 활성공통엔진은부모`engine.py`이며정규실행설정은부모`engine-config.json`과동일합니다. 부모의장부·시세·모델을복제하지않고이어사용합니다.
- `work/archives`:검증된원본파일. `work/data/external.sqlite3`:분봉집계. `work/status.json`:진행상태. 운영자료는GitHub에공개하지않습니다.
- `docs/요구사항_및_데이터계약.md`:요구변경·저장schema·분리/보호조건의상세기록.

## 운영

기존2026컨테이너에서프로젝트root를작업폴더로하여실행합니다.

```powershell
& 'C:/Program Files/Docker/Docker/resources/bin/docker.exe' exec -w '/workspace/2026/Upbit 5-Coin Project' 2026 .venv/bin/python 3차/manage.py status
```

`status`대신`start`·`stop`·`restart`를사용할수있습니다. 이명령의정지는외부수집기만대상입니다. 전체모의운영정지는부모`운영.ps1 stop`도함께실행해야합니다. 정상종료시간초과는오류로보고하고다른프로젝트를강제종료하지않습니다.

대시보드는기존 http://127.0.0.1:8765/ 를사용합니다. 초기자료준비는학습완료100%와구분해표시합니다. 전체운영에는컴퓨터·Docker·프로젝트서비스가계속실행되어야합니다. 컨테이너재시작후수집기와기존감독서비스를다시확인해야합니다.

## 용량과 한계

50GB는실제검증·처리된고유압축파일바이트목표이며메모리에50GB를동시에올리는뜻이아닙니다. DB인덱스·임시복제·압축해제중복파일로목표를채우지않습니다. 원시체결은학습용분봉통계로집계하므로원시체결건수·고유분봉수·학습행수는서로다릅니다. 최종파일단위로최대6GB정도목표를초과할수있습니다.

현재다운로드와준비중이며50GB확보·새모델학습·수익검증을완료했다고보고하지않습니다. 실제수치는`work/status.json`과대시보드에서확인합니다. 통제된작은파일·합성DB시험은실제50GB학습성적이아닙니다.

아카이브의현재파일·해시·디스크여유20GB·필수schema를검사합니다. 해시캐시는파일동일성변경또는1시간에재검증하며기동시다시검사합니다. 공식CHECKSUM은아카이브재사용시다시확인합니다. 같은권한의공격자가소스와상태까지고치는상황에대한서버보증경계는아닙니다. 과거실제공개가용시각의전송지연을복원한자료가아니므로후속실시간모의검증도별도로필요합니다.
