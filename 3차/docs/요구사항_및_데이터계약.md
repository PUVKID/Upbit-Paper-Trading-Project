# 3차 외부 대용량 자료 연구

## 최신 정정

같은 날 후속 사용자 요청으로 아래 초기 30GB 목표와 자료 준비 중 기본 학습 계속 조건은 대체됩니다.

최종 흐름은 외부 고유 아카이브 50,000,000,000바이트 다운로드·검증·청크 처리 완료 →GPU 초기 학습 →이후 업 비트 요청당 200개 새 봉을 중복 없이 누적하며 재학습입니다.

진행 중인 기존 학습 회차는 정상 종료하고 다음 새 학습은 50GB 준비를 기다립니다.

모의매매·기존 포지션 청산은 항상 별도 진행합니다.

같은 50GB를 매회 다시 다운 받거나 최근 200개만으로 모델을 덮어쓰지 않습니다.

외부 특징 모델에 필요한 최신 보조 시세도 계속 갱신합니다.

`training_ready`는 단순 범위 조건이 아니라 SHA 검증과 적재를 마친 고 유 아카이브`ingested_archive_bytes`50GB 이상 및 5 종목 최신성·최근 14일 98%이상 완성 분봉을 모두 만족해야 합니다. `verified_archive_bytes`와`ingested_archive_bytes`를 구분하고 후자가 학습 시작 조건입니다.

실제 압축 파일 하나의 크기만큼 목표를 초과할 수 있으며 기존 디스크 여유 20GB 경계는 유지합니다. `external.wait_for_dataset=true`이면 조건 미달 시 trainer는 실측 다운로드 상태를 남기며 유한 간격 폴 링하고 학습 호출·가짜성공회차·오류폭주를 만들지 않습니다. false인 기존 설정과 구 manifest는 호환합니다.

아래 이전 요구 기록은 삭제하지 않으며 충돌 시 이 절이 우선합니다.

확인 일2026-10-30. 사용자는 새 차수에 외부 거래소 자료 약 30GB를 모아 GPU 학습을 확대하고 업 비트 현물 모의매매를 이어 가기를 요청했습니다. 기존 보존 대응 표에 1차·2차를 확인했으며 이번 3차는 이전 결과를 덮어 쓰지 않습니다.

## 경계

실제 주문·외부 알림·계좌 초기화·공유 컨테이너 재시작은 하지 않습니다.

정확도 100% 또는 수익은 보장하지 않으며 전체 표본 정확도·다수클래스 기준선·MacroF1·시간 순 후속 평가·비용 차감 손익으로만 판정합니다.

기존 중립·승격·손실·출금 불가·잠금 시험 조건을 유지합니다.

데이터 파일 30GB 자체는 성능 지표가 아닙니다.

새 자료는 3차/work 아래에만 저장합니다. 기존 업 비트 DB·계좌·모델은 부모 프로젝트 work를 이어 사용하며 복사하거나 초기화하지 않습니다. 데이터 수집 작업은 기존 학습·모의 매매를 방해하지 않는 별도 프로세스입니다. GPU 개선까지의 부모 engine.py를 보존하고 공유 연결 지점만 최소 수정합니다.

## 외부 자료

Binance Vision의 공식 spot monthly/daily klines 및 aggTrades 아카이브를 사용합니다.

BTCUSDT·SOLUSDT·ETHUSDT·XRPUSDT·DOGEUSDT와 업 비트 KRW5 종목 대응은 고정합니다.

원화 가격으로 둔갑시키거나 레코드를 출처 구분 없이 기존 candles에 넣지 않습니다.

공개 키 없이 시장 자료 GET만 허용하고 실제 주문 API는 사용하지 않습니다.

수집 목표는 검증 한 압축 아카이브 30,000,000,000바이트이며 복제·압축 해제 중복·DB 인덱스로 용량을 채우지 않습니다.

실제 확보 량·검증된 고유 파일 수·고유분봉수·학습 행수는 별개입니다.

파일을 30GB 이상 메모리에 동시에 적재하지 않고 ZIP을 스트리밍 청 크로 집계합니다.

가용 디스크 최소 20GB 여유를남기며파일별유한재시도와 HTTP404·429·5xx를 구분합니다.

오래된 파일 갱신이 가능하므로 SHA256 CHECKSUM을 검증하고 원본/출처/단위/기간을 기록합니다.

Binance 공식 문서에 2025 이후 spot 아카이브의 마이크로 초 변경이 명시되어 있습니다.

기존 밀리 초와 구분해 UTC로 정규화하고 완성분만 저장합니다.

월간·일 간 중복은 minutePK로 중복 학습하지 않습니다.

원시 체결은 1분 OHLCV/거래 대금/체결 수/주도 매수 대금을 스트리밍 집계하며 이를 실제 학습 특징에 사용합니다.

원시 파일 용량을 학습 행수로 부풀리지 않습니다.

## 저장 계약

`3차/work/data/external.sqlite3`의`bars`:

`symbol TEXT, open_time INTEGER, open REAL, high REAL, low REAL, close REAL, volume REAL, quote_volume REAL, trade_count INTEGER, taker_quote_volume REAL, source TEXT, PRIMARY KEY(symbol,open_time)`.

open_time은 UTC 밀리 초분 시작 정수이며 완료 시각은 open_time +60000입니다. 가격·양수·OHLC·체결 수·주도 대금 범위를 검사합니다. 0 거래량 봉은 허용하되 미래 완성 봉은 저장하지 않습니다. SQLite/WAL은 Linux 안에서만 엽니다. 부모콜렉터가스키마와수집·정규화를 소유합니다.

`3차/work/status.json`은`schema_version=1`, `training_ready`bool, `updated_at`UTC ISO, `verified_archive_bytes`, `target_archive_bytes`, `unique_minute_rows`, `markets`symbol별`rows,first_open_ms,last_open_ms`, `state`, `error`를 가집니다.

준비 판정은 5 종목 각각 최소 30일 이상 범위·최소 20000 완성 분봉·최신 봉 5분 이내·스키마 일치입니다.

범위 30일이 연속 30일을 보장한다는 뜻은 아니며 결 측은 특징 결 측으로 남깁니다.

수집 중에는 기존 기본 학습을 계속하며 외부 준비 완료 시 다음 회차부터 외부 특징을 사용합니다.

수집 오류는 상태와 로그로 노출하고 누락을 성공으로 숨기지 않습니다.

## 학습 연결

준비 판정 보완: 단순한 처음/끝 범위만으로 중간 공백을 준비 완료로 처리하지 않도록 각 종목 최근 14 일의 완성 분봉 98%이상도 필요합니다.

이 검사는 symbol/open_time 기본 키 범위별로 조회하여 전 이력 반복 스캔을 하지 않습니다.

일봉/월 봉 아카이브가 아직 제공되지 않았다는 404는 자료 없음으로 별도 기록하며 네트워크 오류와 구분합니다.

deep 작업자는 engine.py와 3차/external_features.py,tests/test _external _features.py를 소유합니다.

기본 설정에 external.enabled =`false|true|"auto"`, db_path/status_path를 명시하며 모든 경로는 프로젝트 3차/work 안에서 검증합니다. auto는 한 학습 회차 시작에 준비 판정과 true/false를 동결해 manifest에 기록합니다.

기존 manifest에 설정이 없으면 기존 92 특징 경로를 유지합니다. true인데 자료/스키마가 손상되면 명시적 오류이며 조용한 기본 모델 대체는 금지합니다.

외부 1분봉의 닫힌 시각을 UTC로 맞춘 뒤 변화율·거래량 비율·변동성·주도 매수 비율 등 가격 단위가 없는 특징을 과거 방향으로 결합합니다.

USD/USDT 가격을 KRW 정답이나 체결 가격으로 쓰지 않습니다.

외부 가격 수준 자체는 입력하지 않습니다.

최신 특징은 외부 자료가 준비된 최신 닫힌 분봉까지만 사용합니다.

무제한 forwardfill·미래 시간 결합·결 측 0 채움 금지.

튜닝/후속 평가의 고정 분리와 보호 기간은 유지합니다.

모의 추론은 manifest에 동결한 설정을 따라 동일한 특징을 사용합니다. 외부 누락·오래됨이 면 신규 매수 보류 사유를 남기고 기존 손 절/청산은 계속합니다. 준비 자료가 충분해지기 전 기존 92 특징 모델 운용은 계속합니다. 자동 교체는 기존 정규 학습과 승격 경계만 통과하며 강제 적용은 하지 않습니다.
