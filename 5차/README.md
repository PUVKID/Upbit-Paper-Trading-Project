# 5차 월 경계 누락 복구와 초기 연구 재개

50GB 외부 아카이브를 검증·적재한 뒤에도 최근 분봉이 부족해 GPU 연구가 대기하는 원인을 수정했습니다. 활성 코드 경로는 유지하고, 이전 자료·모델·계좌를 초기화하지 않습니다.

## 확인한 원인

적재량은 50,236,121,507바이트였으나 다섯 종목 모두 최근 14일 분봉이 18,969개로, 기존 98% 기준인 19,756.8개에 미달했습니다. 확인한 BTC 누락 구간은 2026-10-31 03:57~23:47 UTC의 1,191분입니다. 이는 원본 체결 오류를 격리했던 4차의 문제와 다릅니다.

기존 준비 계획은 직전 월의 월별 아카이브와 현재 월의 일별 아카이브만 요청했습니다. 월별 원본 공개 지연·기존 수집 중단이 겹치면 전월 말의 일별 자료를 다시 확보할 경로가 없습니다. 최신 1,000개 분봉 조회도 이미 지나간 공백을 복구하지 못합니다.

## 수정

[활성 수집기](../3차/external_data.py)의 `bootstrap_plan`에서 직전 월별 자료를 유지하면서, 이번 달 이력과 최근 14일에 해당하는 완료 UTC 날짜의 일별 원본을 요청합니다. 월·연도·윤년을 날짜 API로 처리하며 같은 파일은 한 계획에 한 번만 포함합니다. 최근 날짜부터 확인합니다.

기존 체크섬·내용 검증·완료봉·고유 저장을 재사용합니다. 50GB를 DB나 압축해제 용량으로 대체하지 않으며, 최근 14일 98% 커버리지·최신성·GPU 전용 적합·평가·승격 기준은 완화하지 않습니다. 이미 저장된 분봉을 덮어쓰거나 임의 보간하지 않습니다.

[회귀 검사](../tests/test_recent_archive_plan.py)는 월 경계·연도 변경·윤년·현재 월 이력·중복 요청·완료 UTC 날짜와 다른 시간대 입력을 확인합니다. 실제 자료와 통제된 회귀 검사를 구분하며, 소프트웨어 검사 통과를 학습 성적이나 수익으로 해석하지 않습니다.

## 유지한 운용

[4차 두 트랙 계약](../4차/docs/두트랙_연구계약.md)은 그대로입니다. 최초 50GB 준비 후 연구 한 회차를 수행하고, 완료 후 명시 요청을 기다립니다. 이후 요청마다 그 시점의 실제 적재량보다 새 고유 자료 2GB를 확보한 뒤 연구 한 회차를 수행합니다. 이번 재개가 새 2GB 요청을 추가하지는 않습니다.

모의매매와 최신 시세는 독립 트랙입니다. 수집기만 수정본으로 재실행했으며 감독 프로세스·모의매매·공유 컨테이너는 재시작하지 않았습니다. 원금 1,000만원과 기존 장부를 유지하고 실제 주문·외부 알림·강제 거래를 추가하지 않습니다.
