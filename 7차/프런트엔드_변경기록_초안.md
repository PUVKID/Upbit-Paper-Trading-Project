# 연구 대시보드 화면 재구성

완료 포인터 뒤 상태 저장이 실패하는 경계를 보완해 `has_status_warning`을 추가했습니다. 모델 완료와 화면 기록 재동기화 경고를 기존 우측 요약·상세에서 구분하며, 경고만으로 검증된 가중치를 실패로 표시하지 않습니다. 관련 통제 상태 1개를 추가한 최신 브라우저 검사는 96항목입니다. 아래의 95항목 기록은 앞선 실제 검사 이력으로 보존합니다.

추가 실제 완료 화면 검토에서 이전 단계가 대기로 남는 문제를 보완했습니다. 저장·재로딩 검증까지 끝난 연구에만 자료 확보·학습·검증의 완료 상태를 같은 DOM·Three.js 상태로 표시하며 매매 적용은 완료로 만들지 않습니다. 새 상태 회귀를 포함한 최신 순수 회귀는 9개입니다. 아래 8개·95항목 기록은 해당 시점의 실제 검사 이력입니다.

이 문서는 구현 중 작성한 제목을 보존한 7차 화면 상세입니다. 최종 통합 관측과 완료 범위는 [변경 기록](변경기록.md)을 따릅니다. 최초 구현의 중간 실패와 최종 수리 결과를 아래에서 구분합니다. 부모의 실제 캡처 검토 후 우측 상태 라벨 폭을 보완했고 같은 브라우저 95항목을 다시 통과했습니다. 새 검사 캡처는 `FRONTEND_EVIDENCE_DIR`로 별도 경로에 보존할 수 있습니다.

## 변경 범위

- `web/index.html`: 기존 학습 화면 첫 영역을 현재 작업, 5단계 장면, 우측 진행과 다음 단계, 하단 가상투자 계좌와 최근 기록 순서로 재구성했습니다. 기존 상세 표와 진단 ID는 보존했습니다.
- `web/style.css`: 화이트·옅은 민트, 나눔고딕 Bold 700, 좌측 탐색, 5단계 고정 열과 작은 화면 줄바꿈을 적용했습니다. 기존 다크 테마는 유지합니다.
- `web/scene.js`: 클라우드·자료 묶음·GPU 팬·검증 렌즈·문서 모형을 실제 Three.js 형상으로 구성했습니다. 현재 API 단계만 움직이며 시간에 따른 가짜 단계 전환은 없습니다. 화면 정지·모션 축소·화면 밖 정지와 WebGL 문자 대체를 유지합니다.
- `web/app.js`: 기존 상태 API를 사용해 연구 상태와 실제 계좌·최근 기록을 표시합니다. `foundation_research`가 비어 있으면 미실행으로 표시하고 새 모델은 기존 가상투자 모델과 다른 별도 연구 후보로 구분합니다. 오류 원문은 사용하지 않고 `has_error` 상태를 사용합니다.
- `tests/frontend-research-qa.cjs`: 실제 API·통제된 화면 입력·작은 화면·캔버스 픽셀·모션·상태 경계를 검사하는 프런트엔드 검사를 추가했습니다.

새 정적 파일 경로·외부 CDN·새 의존성은 없습니다. 기존 번들 빌드는 동일 크기로 생성됩니다. 백엔드·계좌·매매 기준·PBL 프로젝트는 이 화면 변경의 수정 대상이 아닙니다. 이전 차수는 보존합니다.

## 확인 범위

UI 빌드, JavaScript 구문, 기존 종목 옵션 회귀 1개, 정적 검사 117항목이 통과했습니다. 실제 화면은 1513·1024·390·320px에서 캔버스 픽셀과 가로 넘침·단계 글자 잘림을 확인했습니다. 5단계 통제 입력에서 움직임·정지·축소 모션·오류·HTML 입력 비실행·별도 후보 표시를 검사했습니다.

브라우저 전체 검사에는 검사 스크립트가 새로고침마다 초기 테마를 덮어쓰는 결함이 남아 있습니다. 실패는 비공개 검증 기록에 보존하며 전체 통과로 표현하지 않습니다. 별도 진단에서 앱의 dark 저장값과 새로고침 후 dark 복원을 관측했습니다. 최종 독립 검증·전체 공개 파일 비교·공개 반영·원격 확인은 별도 완료 절차입니다.

## 비교와 한계

참조 디자인의 좌측 탐색·큰 작업 제목·민트 장면·우측 진행·하단 핵심 수치와 기록의 구조를 반영했습니다. 참조의 예시 날짜·수치·성능·정지 이미지는 사용하지 않았습니다. 참조와 실제 화면은 직접 이미지로 대조했으나 픽셀 동일성을 주장하지 않습니다. 렌더링되는 장면은 처리 흐름의 상징이며 처리량·학습 성공·수익을 증명하지 않습니다.

원본 전체 비교와 공개용 최종 설명 통합은 프로젝트 담당자가 수행합니다. 운영 캡처·실패 로그·내부 인계 기록은 공개용 자료가 아닙니다.

## 최종 수리와 재검사

위 미완료 검사는 최초 실행의 기록이며, 이후 다음 범위를 수리·재검사했습니다. 삭제된 파일의 HTML script 참조를 제거했고, 기존 연구의 적용 표시는 비어 있지 않은 현재 회차와 승격 보고서의 회차가 일치할 때만 허용합니다. 회차가 다르거나 누락되면 적용으로 표시하지 않으며 사전학습 후보는 기존 모델의 승격과 분리합니다.

테마 검사 초기화는 저장값이 없을 때만 수행해 새로고침 후 dark 복원 기대를 유지했습니다. 화면 대기는 실제 상태 수신·렌더 완료로 강화했습니다. 계좌 원장·API 수치·후속 평가 표시와 기존 수락 기준은 변경하지 않았습니다.

- 작은 프런트엔드 회귀 5개: 수정 전 3실패·2통과, 같은 검사로 수정 후 5통과.
- 실제 API + 통제된 입력을 사용한 Edge headless 브라우저 검사 65항목 통과, 런타임·콘솔 오류 0개.
- 1513·1024·390·320px 화면에서 가로 넘침·단계 글자 잘림·실제 캔버스 픽셀을 검사했습니다.
- 5단계 픽셀 모션·정지·운영체제 모션 축소, 테마 전환·저장·재로드 복원, 후보 준비·오류·0값·HTML 입력 비실행을 검사했습니다.
- 모바일 5종목 학습 필터와 자료·체결 행을 실제 API와 대조하고 기존 계좌 평가·후속 평가 정확도 표시를 확인했습니다.
- WebGL 미지원과 연결 소실에서 문자 단계·실제 계좌·상태를 유지하는지 검사했습니다.
- UI 빌드와 기존 종목 옵션 회귀 1개도 다시 통과했습니다.

이 검증은 구현자의 로컬 Playwright·Edge headless 검사입니다. 별도 검증자의 독립 검사나 부모의 CUA 화면 검증으로 대체하지 않으며, 실제 사전학습 모델 학습 성공·매매 적용·수익 향상을 뜻하지 않습니다. 이전 실패는 내부 기록에 보존했습니다.

## 실제 연구 계약 반영

사전 점검·자료 추출·모델 불러오기는 데이터 정리, 추가 학습은 GPU 학습, 체크포인트 확인·후속 평가는 검증으로 연결합니다. 연구 완료는 검증 완료로 표시하고 매매 적용과 구분합니다. 새 미사용 자료 대기와 중단도 별도로 표시하며 비활성 상태에서는 모형을 임의로 움직이지 않습니다.

사전학습 트랙 요약에는 해당 연구의 실제 스텝·행 수·장치·문맥 길이·배치 크기만 사용합니다. 학습률·평가 지표는 펼친 상세에서 확인합니다. 기존 9시간봉·3클래스 안내와 기존 상세에는 XGBoost 모델임을 명시해 5분봉 종가의 60분·12스텝 분위수 예측 연구와 혼합하지 않습니다.

상대 MAE와 종가유지 상대 MAE는 원점 종가로 정규화한 절대오차 평균의 비율을 백분율로 표시합니다. 원 단위 오차가 아닙니다. 방향 정확도도 비율을 백분율로 표시하며, 순수익률·거래 수·평가 오차가 없으면 미평가를 유지합니다. 체크포인트 검증·후보 준비·현재 매매 적용은 서로 다른 상태입니다.

## 프런트엔드 검사 실행

로컬 상태 서버가 `http://127.0.0.1:8765`에서 실행 중이어야 합니다. 기존 의존성 외에 이 변경에서 새 패키지를 추가하지 않았습니다.

```sh
node --test tests/frontend-workflow.test.cjs
node tests/frontend-research-qa.cjs
```

브라우저 검사에서는 기본적으로 설치된 `playwright` 모듈과 해당 모듈의 Chromium을 사용합니다. 외부에 이미 설치된 Playwright를 사용하려면 `PLAYWRIGHT_MODULE`에 실제 모듈 경로를, 별도 Edge·Chrome을 사용하려면 `BROWSER_EXECUTABLE`에 실제 실행 파일 경로를 해당 명령의 프로세스 환경으로 지정합니다. 사용자별 절대 경로는 검사 소스에 포함하지 않습니다. 운영체제의 전역 환경·인증 설정을 변경할 필요는 없습니다.

최종 실제 계약 반영 후 같은 회귀 8개, 환경변수 방식으로 실행한 브라우저 검사 95항목, 종목 옵션 회귀 1개, 정적 122항목과 UI 빌드가 모두 통과했습니다. 이 결과는 앞서 기록한 중간 실패를 지우지 않습니다. 별도 verifier·부모의 실제 화면 확인·공개 전체 비교·원격 확인은 이 구현자 검사와 별개입니다.
