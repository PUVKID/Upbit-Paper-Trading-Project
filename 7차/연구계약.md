# 독립 사전학습 연구 실행 계약

## 범위

이 실행기는 공개 Chronos-2의 가중치를 실제 Upbit 과거 시세로 추가 학습하는 단일 회차 연구 도구입니다. 기존 6차 수집·연속 연구·검증 incumbent와 원금 1,000만원의 모의계좌는 별도로 유지합니다. 기존 엔진·대시보드·장부·운용 모델 포인터를 변경하지 않습니다. 정확도 또는 수익을 보장하지 않습니다.

## 실제 실행

기존 `2026` 컨테이너의 작업 위치는 `/workspace/2026/Upbit 5-Coin Project`입니다. 시스템 인터프리터로 실행합니다.

```text
/opt/venvs/torch/bin/python3 -B -X utf8 7차/shadow_research.py --help
/opt/venvs/torch/bin/python3 -B -X utf8 7차/shadow_research.py --config 7차/foundation-config.json --once
```

코드 기본값은 50 step, context 256개, batch 8, 예측 지평 12개 5분봉(60분), 학습률 0.000001입니다. 이번 실제 설정 파일은 도지코인의 평가 구간 최장 연속 길이 250봉을 확인해 context를 192개로 지정했습니다. 누락 봉 보간이나 보호 구간 제거 기준 변경은 하지 않았습니다. 더 큰 실험은 별도 검토한 설정 JSON으로 지정할 수 있으며 한 번의 실행은 설정된 step과 시간 상한 안에서 끝납니다. 자료 부족 시 종료 코드 3, 중복 실행은 2, 사용자 중단은 130, 일반 오류는 1입니다. 완료는 0입니다. 동일 검증 구간을 자동 반복하는 기능은 없습니다.

## 의존성과 사전학습 원본

`research-requirements.txt`는 부모가 실제 설치·import 검사한 직접 의존성 목록입니다. 전이 의존성까지 포함한 완전한 lock 파일은 아닙니다. 시스템의 torch·numpy·pandas를 다시 설치하지 않습니다. runner 프로세스에만 `7차/work/python-packages`를 추가하며 기존 `.venv`, 공유 환경, 다른 프로세스의 검색 경로는 변경하지 않습니다.

원본 모델은 `amazon/chronos-2`, 고정 revision은 `29ec3766d36d6f73f0696f85560a422f50e8498c`입니다. 부모가 다운로드한 `7차/work/pretrained/<revision>`의 실제 파일과 `download-evidence.json`을 사용합니다. 모델 SHA256은 `ddcda3c7508bf2528087723e98a20707cc04b7f370ae275a9fd88078ddba4f42`이며 공식 LFS 값과 대조합니다. runner는 다운로드하지 않으며 온라인 모델 이름이나 변경 가능한 `main`으로 로드하지 않습니다. 로드는 로컬 전용·`trust_remote_code=False`입니다. 새 링크를 생성하지 않고 입력·출력 경로의 링크를 거부합니다.

## 데이터와 누수 경계

운영 SQLite는 Linux 안에서 `mode=ro`, `PRAGMA query_only=ON`과 읽기 트랜잭션으로만 엽니다. 실제 입력은 다섯 KRW 종목의 완료된 5분 OHLCV에서 추출한 종가입니다. UTC 시각·봉 길이·정렬·중복·OHLC·거래량과 읽기 행 상한을 검사합니다. 상한 초과 시 일부 자료로 조용히 대체하지 않습니다. 추출한 OHLCV의 해시, 종목별 실제 읽은 행과 학습에 사용한 행, 기간을 구분합니다.

학습·튜닝·후속 검증을 시간순으로 분리합니다. 고정 보호 시험인 2026-10-19~20 UTC와 기존 감사 DB의 소비 시험 기간을 제외합니다. 보호 기간에 봉 자체가 겹치는 경우도 보수적으로 제외하며, 시각 공백이나 보호 구간을 가로지르는 창을 만들지 않습니다. 모든 학습·튜닝 target은 해당 구간 안에만 있습니다. 검증 창의 context는 target보다 과거이고, 코인 간 교차 학습 추론은 끕니다.

초기 50GB 조건은 초기 bootstrap 완료 상태·요청·원본 보고서·manifest·실제 기존 모델 해시의 결합과 현재 보고된 고유 적재량으로 확인합니다. 다음 2GB 목표의 `training_ready=false`를 초기 연구 미완료로 해석하지 않습니다. 이 runner는 Binance 분봉을 입력하지 않으므로 현재 Binance 최신성·14일 커버리지를 별도 의무 게이트로 만들지 않습니다. 기존 엔진의 해당 검사는 수정하지 않았습니다. 외부 전체 원본을 재해시하거나 전체 외부 자료를 Chronos 학습에 사용했다는 주장도 하지 않습니다.

## CUDA와 연속 checkpoint

CUDA 미지원 시 CPU로 대체하지 않습니다. 로드한 모델뿐 아니라 공식 `fit()`이 복제해 실제 Trainer에 넘긴 모델도 첫 optimizer step 이전 `on_train_begin`에서 검사합니다. 이후 각 step에도 실제 모델 장치를 검사합니다. 완료 step, 유한 loss, 학습 전후 전체 파라미터 해시 변화가 있어야 완료 후보를 만들 수 있습니다.

최초 정상 완료 전에는 검증된 고정 사전학습 원본을 사용합니다. 정상 완료 뒤에는 `7차/work/knowledge.json`에 결합된 checkpoint만 이어받습니다. 부모·조상 manifest와 모델 파일 해시·모델 revision·CUDA·완료 근거를 다시 확인하며, 손상·누락을 원본 초기화로 우회하지 않습니다. 완료 manifest가 있는데 포인터가 없으면 거부합니다. 이는 **완료 가중치 연속 추가학습**이며 optimizer·scheduler·RNG의 중간 resume가 아닙니다.

checkpoint를 로드한 뒤 가중치 해시와 동일 context의 예측을 저장 전과 대조합니다. 검증된 완료 산출물만 원자적 manifest와 별도 연구 포인터에 결합합니다. 매매용 `work/models/current.json`에는 쓰지 않습니다.

### 완료 확정과 표시 복구

완료 확정 경계는 연구용 `knowledge.json`의 원자적 포인터 커밋입니다. 먼저 회차의 `completion.json`에 flat 완료 Status 스냅샷을 원자적으로 저장합니다. 이 파일의 실제 바이트 SHA256을 manifest와 knowledge의 동일한 `completion_sha256`에 결합합니다. completion 스냅샷에는 manifest 해시를 넣지 않아 순환 결합을 만들지 않습니다. knowledge는 `run`, `manifest_sha256`, `completion_sha256` 세 필드입니다.

커밋 전 실패는 비정상 종료하고 이전 연구 포인터를 유지합니다. 포인터 교체 후 디렉터리 동기화에서 예외가 나더라도 실제 포인터·manifest·completion을 다시 읽어 완료 결합을 확인한 경우에만 커밋 후 경로로 처리합니다. 완료를 확인할 수 없으면 비정상 종료하며 커밋 성공을 추정하지 않습니다.

커밋 뒤 공용·회차 상태 캐시의 저장 실패는 완료된 모델을 `verified=false`로 되돌리지 않습니다. 원문·traceback·당시 실제 누적을 회차의 `finalization-errors` 아래에 별개로 보존하고 두 차례 표시 최종화를 시도합니다. 저장 오류가 지속돼도 완료 커밋을 검증할 수 있으면 `state=complete`, `candidate_ready=true`, `checkpoint_verified=true`, `has_status_warning=true`를 반환하고 CLI는 0입니다. 공용 캐시만 쓸 수 있으면 동일 완료 상태와 경고를 거기에 남깁니다. 캐시도 전혀 쓸 수 없으면 부모 API의 봉인 스냅샷 읽기 fallback과 CLI 경고가 필요합니다.

재시작은 새 회차를 만들기 전에 완료 스냅샷과 두 상태 캐시의 해시를 대조합니다. 불일치한 신규 형식의 커밋은 정상 부모·완료 스냅샷을 다시 검증한 뒤 표시 저장만 복구하고 반환합니다. 모델 로드·학습·예측·새 평가 예약은 하지 않습니다. 완료 스냅샷이 없는 기존 실제 GPU 산출물은 이전 형식 그대로 읽으며 자동 마이그레이션하거나 포인터·manifest를 재작성하지 않습니다.

두 상태 캐시는 봉인된 completion dict를 시각까지 그대로 `atomic_json`으로 저장합니다. 정상 최종화 뒤에는 두 파일의 raw SHA가 `completion_sha256`와 같아 복구 경로가 `None`을 반환하고 다음 회차를 허용합니다. 단, 현재 공용 상태가 명시적으로 다른 run의 대기·오류·학습 상태라면 이전 완료로 덮어쓰지 않고 복구를 건너뜁니다. 공용 캐시가 없거나 손상돼 run을 확인할 수 없는 경우에는 신규 완료 커밋 전체의 엄격 검증 후 표시만 복구합니다. 완료 스냅샷·manifest의 해시가 틀리면 복구하거나 완료를 추정하지 않고 비정상 종료합니다.

부모 API의 읽기 계약은 다음과 같습니다. 현재 `status.run == knowledge.run`인 동일 회차에서만 작은 manifest 파일의 바이트 해시와 `knowledge.manifest_sha256`, completion 파일의 바이트 해시와 양쪽 `completion_sha256`를 대조하고 완료 스냅샷을 우선합니다. 오래된 캐시 또는 `status.has_status_warning=true`는 표시 저장 경고로 구분합니다. 다른 활성 회차를 이전 완료 스냅샷으로 덮어쓰지 않습니다. 가중치 전체 해시는 실행·재시작 검증에서만 확인하며 UI의 매 갱신마다 재계산하지 않습니다.

임의의 지속 I/O 고장에서도 디스크 기록이나 화면 동기화를 보장할 수는 없습니다. 최종화 오류 기록 자체도 저장할 수 없으면 원문과 기록 실패를 비공개 실행 stderr로 함께 내보냅니다. 완료 증거 파일 자체를 읽거나 검증할 수 없는 경우는 단순 표시 경고와 구분해 비정상 종료합니다. 이전 실패와 평가 예약을 삭제하거나 다시 학습해 이 경계를 우회하지 않습니다.

## 실패 회차의 평가 노출

재로드 검증용 probe도 검증 context를 사용하므로 그 첫 예측보다 먼저 평가 기간 전체를 원자적으로 예약합니다. `7차/work/exposures/<run>.json`은 실행 ID·모델 revision·부모·검증 기간·실제 data.json 해시와 추출 자료 해시에 결합됩니다. manifest 또는 연구 포인터 저장이 실패해도 예약을 남깁니다.

다음 실행은 완료 부모의 계보와 실패 회차를 포함한 모든 평가 예약의 상한을 읽습니다. 예약의 변조·자료 불일치·실패/완료 기록이 참조한 예약 누락은 거부합니다. 평가 기간이 끝난 뒤 새 context와 target이 충분히 모일 때까지 준비 대기로 종료합니다. 이 보수적 정책은 아직 예측하지 않은 예약 기간도 재사용하지 않습니다.

## 성과와 상태 API

`validation_mae`와 `baseline_mae`는 원화 단위가 아닙니다. 각 창의 마지막 context 종가로 절대오차를 나눈 뒤 모든 예측 시점에서 평균한 **상대 절대오차**입니다. baseline은 같은 창·정답에 대해 마지막 종가를 유지하는 예측입니다. `direction_accuracy`는 각 창 마지막 지평의 상승·하락·동일 방향 일치 비율이며 기존 3클래스 정확도와 다릅니다. 표본 창 수와 평가 범위는 비공개 평가 기록에 보존합니다.

실제 과거 비용 기반 매매 평가 어댑터는 구현하지 않았습니다. 따라서 `net_return`과 `trades`는 항상 null, `promote`는 false입니다. `candidate_ready=true`는 저장·재로딩 검증을 통과한 연구 후보 준비 상태일 뿐 본계좌 적용이나 수익 검증 승인이 아닙니다.

실제 callback의 step·loss와 단계·시각은 `7차/work/status.json`에 원자적으로 기록합니다. API가 사용하는 기존 whitelist에 맞춘 필드와 비공개 오류의 존재 여부를 제공합니다. 오류 원문·traceback은 회차의 `failure.json`에 보존하며 상태의 오류 문구에는 원문이나 인증값을 넣지 않습니다. 실패 누적 횟수는 유일하게 확인된 실제 라우팅 상태에서 읽고, 확인할 수 없으면 null로 둡니다.

## 보존과 중단

`7차/work/STOP` 파일 또는 SIGTERM/SIGINT를 확인합니다. STOP 파일을 runner가 제거하거나 사용자 중단을 자동 재개하지 않습니다. `runner.lock`의 비차단 Linux 잠금으로 중복 실행을 막고 기존 실행의 상태를 덮어쓰지 않습니다. 디스크 여유를 실행 전·완료 저장 전에 검사하고, 부족하면 자료 삭제 대신 실패합니다. 자동 checkpoint 정리도 하지 않으며 `save_total_limit=None`입니다. 모델과 과거 자료·실패 이력을 삭제하지 않습니다.

## 검증 범위

신규 회귀는 자료·공백·보호 기간·계보·실제 복제 모델의 CUDA 사전 거부·실패 평가 예약·변조/누락·중복 잠금·STOP·원자 저장·지표·CLI 경계를 검사합니다. CPU 대역 모델 검사는 GPU 학습 성공이나 수익의 증거가 아닙니다. 실제 GPU 추가학습, 독립 verifier 검증과 공개 반영의 최종 판단은 부모가 별도로 수행합니다. 로컬 해시·영수증은 서버 보증 신원 인증이 아닙니다.
